# SINVER
![Список серверов в SINVER](doc/main.png)

SINVER (Server INVentorisation) — веб-приложение для хранения информации об инфраструктуре и управления записями DNS. Оно объединяет сведения о серверах, IPv4- и IPv6-адресах, поддоменах, хостингах и DNS-зонах в одном интерфейсе.

С помощью SINVER можно:

- вести список серверов и связывать их с хостингами;
- назначать роли и цвета серверам, адресам и поддоменам;
- направлять один поддомен на несколько IP-адресов;
- просматривать план изменений DNS и публиковать записи в PowerDNS через PostgreSQL;
- генерировать файл зоны для ручной установки на BIND9.

> **Это MVP, версия `0.0.0`.** Приложение находится на ранней стадии разработки. В нём нет встроенной аутентификации и разграничения доступа; для удалённой работы необходим защищённый вход через NGINX. Перед использованием с действующими DNS-зонами изучите [текущие проблемы](doc/11_Current_Issues_RU.md) и проверьте работу на отдельной тестовой зоне.


Данные об инфраструктуре хранятся в локальной базе SQLite. PostgreSQL используется отдельно для записей PowerDNS.

## Для разработки

Поведение приложения и структура данных описаны в [технической спецификации](Technical_specifications.md). Правила изменения схемы — в [руководстве по миграциям](guidelines/database_version_migration.md); файлы миграций — в [database/migrations](database/migrations/README.md).

Проверки запускаются из каталога репозитория с Python 3.11 или новее. Для проверок приложения нужен Flask, для проверки установки — GNU Make:

```bash
python3 -m unittest discover -s tests -v
python3 tests/maintenance_smoke.py
python3 tests/install_smoke.py
```

Подготовить файлы для пакета без установки в систему можно командой `make DESTDIR=/path/to/package-root install`. Она не создаёт служебную учётную запись и не вызывает `systemctl` на машине сборки. Создание пользователя `sinver`, назначение владельцев файлов и сохранение существующего конфигурационного файла при обновлении должен обеспечить пакет.
