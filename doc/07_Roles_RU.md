# 7. Роли — Roles

[← Назад](06_Subdomains_RU.md) · [Содержание](README_RU.md#содержание) · [Вперёд →](08_Hostings_RU.md)

Вкладка **Roles** хранит справочник назначений серверов, IP-адресов и поддоменов. Например, роль `application` обозначает ресурсы, обслуживающие приложение, а `database` — ресурсы базы данных. Цвет роли помогает различать их в списках.

**Роль — это метка инвентаризации.** Она не предоставляет права доступа, не настраивает сервер и не влияет на состав DNS-записей. У каждого сервера, IP-адреса и поддомена может быть одна назначенная роль либо значение `None` — роль не задана.

## 7.1. Список и поиск

В таблице отображаются:

| Столбец | Значение |
| --- | --- |
| **Color** | Цветной маркер роли. |
| **Name** | Название роли; ссылка открывает её карточку. |
| **Description** | Первые 50 символов описания; полное описание доступно в карточке. `—` означает, что описание отсутствует. |

Форма над списком задаёт условия поиска:

| Поле | Как работает |
| --- | --- |
| **Name contains** | Поиск по фрагменту названия. Например, `app` находит `application`. |
| **Description contains** | Поиск по фрагменту описания. |
| **Color** | Точное совпадение с выбранным цветом. Начальное значение формы — `#8d7b68`. |
| **Sort by** | Сортировка по `name`, `description` или `color`. По умолчанию — по названию. |

**Apply** применяет все заполненные условия одновременно; **Reset** открывает полный список. Сортировка идёт по возрастанию как по тексту, без учёта регистра латинских букв.

> **Особенность текущей версии:** при нажатии **Apply** поле **Color** отправляется всегда. Поэтому поиск по названию также ограничивается выбранным цветом. Чтобы найти `application`, выберите её цвет; чтобы снова увидеть все роли, нажмите **Reset**.

## 7.2. Создание роли

Заполните форму **Add role** и нажмите **Create**.

| Поле | Обязательность и значения | Пример |
| --- | --- | --- |
| **Name** | Обязательно при создании. Уникальное название длиной до 128 символов. | `application` |
| **Color** | Цвет из палитры браузера, обычно в формате `#RRGGBB`. По умолчанию `#8d7b68`. В базе поле обязательно; максимальная длина — 32 символа. | `#3b82f6` |
| **Description** | Необязательный текст о назначении роли. | `Серверы и адреса приложения` |

Названия не нормализуются автоматически: используйте один способ именования и проверяйте пробелы. При повторном использовании уже существующего названия или превышении ограничения сохранение не выполнится; текущая версия может показать общее сообщение **Internal error**.

После создания выберите `application` в поле **Role** карточки сервера `app-01`. Если нужно обозначить отдельное назначение IP-адреса или поддомена, назначьте роль в его собственной карточке.

## 7.3. Карточка роли и связанные ресурсы

В карточке **Role: application** можно изменить те же поля. Общий порядок редактирования описан в [главе о WEB-интерфейсе](03_Web_Interface_RU.md).

Ниже находятся три списка со ссылками на ресурсы:

| Раздел | Какие объекты показаны |
| --- | --- |
| **Servers with this role** | Серверы, у которых эта роль выбрана в поле **Role**. |
| **IP addresses with this role** | IP-адреса с явно назначенной этой ролью. |
| **Subdomains with this role** | Поддомены с явно назначенной этой ролью; рядом с именем указан тип DNS-записи. |

Пустой список обозначен `—`. Эти списки показывают прямые назначения: IP-адрес может иметь цвет роли сервера, но не появляться в списке IP-адресов этой роли.

### Откуда берётся цвет ресурса

| Ресурс | Правило выбора цвета |
| --- | --- |
| Сервер | Цвет назначенной ему роли. |
| IP-адрес | Цвет собственной роли; если её нет — цвет роли сервера. |
| Поддомен | Цвет собственной роли; если её нет — цвет одного из связанных IP-адресов по правилам выше. |

Если у поддомена несколько адресов, сначала выбирается адрес с признаком **Primary**, затем — адрес с меньшим внутренним идентификатором. Это только правило отображения цвета: оно не назначает роль поддомену и не исключает остальные адреса из DNS.

**Пример.** Серверу `app-01` назначена синяя роль `application`, а его IP-адресу роль не назначена. В списке адресов маркер будет синим. Если этому адресу назначить другую роль, его маркер примет её цвет, а роль и цвет сервера сохранятся.

## 7.4. Изменение и удаление

Переименование роли или изменение её цвета действует на все объекты с прямой ссылкой на эту роль. Цвет также обновится у объектов, которые получают его по правилам наследования выше.

Кнопка **Delete role** удаляет роль после подтверждения **Delete role?**. Серверы, IP-адреса и поддомены сохраняются, но их ссылки на удалённую роль очищаются. После этого цвет IP-адреса или поддомена может измениться из-за наследования; цвет сервера без роли отсутствует.

**Сценарий упорядочения инвентаризации:** создайте роль `application`, назначьте её `app-01`, откройте карточку роли и проверьте список **Servers with this role**. Если требуется заменить роль, сначала назначьте ресурсам новую роль, затем удалите старую: SINVER не переносит назначения автоматически.
