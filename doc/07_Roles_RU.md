# 7. Роли — Roles

Вкладка **Roles** (`/roles`) — справочник назначений серверов, IP-адресов и поддоменов. Примеры: `Web`, `Database`, `Public`, `Management`, `API`. Роль помогает отбирать объекты и выделять их цветом.

**Роль обозначает назначение объекта и не управляет доступом пользователей.** У каждого сервера, IP-адреса и поддомена может быть одна собственная роль либо **None**. Роли не задают права, не настраивают службы сервера и не изменяют DNS-записи.

## 7.1. Поля роли

| Поле интерфейса | Обязательность | Смысл и допустимые значения |
| --- | --- | --- |
| **Name** | Обязательно для корректной карточки; форма создания требует заполнения | Уникальное имя роли; максимум 128 символов. Например, `Web`. Начальные и конечные пробелы автоматически не удаляются. |
| **Color** | Обязательно; начальное значение `#8d7b68` | Цветовая метка. Браузер предоставляет выбор цвета и отправляет шестнадцатеричное значение вида `#2f80ed`. База допускает строку длиной до 32 символов; SINVER отдельно не проверяет формат цвета. |
| **Description** | Необязательно | Критерий назначения роли, например `Серверы, обслуживающие HTTP-приложения`. Ограничение длины в схеме базы не задано. |

Придерживайтесь единых имён без лишних пробелов и различий только в регистре: база сравнивает уникальность имён как строки, а не по смыслу. Повторное название или превышение ограничений длины может привести к общему сообщению **Internal error**; известные ошибки проверки описаны в [текущих проблемах](11_Current_Issues_RU.md).

## 7.2. Цвета связанных объектов

| Объект | Откуда берётся цвет |
| --- | --- |
| Сервер | Из назначенной ему роли. Без роли метки нет. |
| IP-адрес | Из собственной роли IP; при её отсутствии — из роли сервера. |
| Поддомен | Из собственной роли поддомена; при её отсутствии — из одного связанного IP по правилу предыдущей строки. Сначала выбирается IP с признаком Primary; при одинаковом приоритете — с меньшим внутренним ID. Если у выбранного IP и его сервера роли нет, метки нет. |

Наследуется **только цвет**. Собственная роль объекта при этом остаётся пустой. Поэтому IP с цветом роли `Web` своего сервера может показывать `—` в столбце **Role** и не попадать в фильтр **Role = Web** на вкладке **IP addresses**.

Если поддомен связан с серверами разных назначений, задайте ему собственную роль: так его цвет не будет зависеть от выбора одного из связанных адресов.

## 7.3. Список и поиск

В таблице показаны **Color**, **Name** и **Description**. Имя открывает карточку. Описание в таблице сокращено до первых 50 символов; полный текст доступен в карточке. `—` означает отсутствие описания.

| Поле поиска | Действие |
| --- | --- |
| **Name contains** | Поиск фрагмента имени. |
| **Description contains** | Поиск фрагмента описания. |
| **Color** | Точное совпадение сохранённого значения цвета. |
| **Sort by** | `name`, `description`, `color`; сортировка по возрастанию. По умолчанию — `name`. Цвет сортируется по строке его кода. |

Условия поиска применяются одновременно. **Apply** применяет их, **Reset** открывает полный список. Правила текстового поиска и общие особенности сортировки приведены в [главе о веб-интерфейсе](03_Web_Interface_RU.md).

**Особенность текущей версии:** при **Apply** браузер отправляет значение **Color**, даже если вы меняли только имя. Начальный цвет `#8d7b68` становится дополнительным фильтром и может скрыть нужные роли. Для полного списка используйте **Reset**. Для поиска по имени без цвета удалите параметр `color` из адресной строки; например, `/roles?role_name=Web&sort=role_name`. Причина описана в [текущих проблемах](11_Current_Issues_RU.md).

## 7.4. Создание и назначение

1. В **Add role** введите имя, выберите цвет и при необходимости заполните описание.
2. Нажмите **Create**.
3. Выберите созданную роль в поле **Role** нужного сервера, IP или поддомена и сохраните этот объект.

Для изменения самой роли откройте её по имени, нажмите **Edit**, затем **Save**. Переименование и изменение цвета отражаются во всех объектах, которым назначена эта роль. Цвет обновляется и у объектов, которые получают его через связанные ресурсы.

В карточке находятся блоки **Servers with this role**, **IP addresses with this role**, **Subdomains with this role**. Каждая строка — ссылка на соответствующий объект. Списки включают только объекты, которым роль назначена непосредственно; объекты с унаследованным цветом в них не входят.

### Пример: разделение публичных и служебных адресов

Создайте роль `Web` с цветом `#2f80ed` и назначьте серверу `web01`. Создайте роль `Management` с цветом `#f2994a` и назначьте дополнительному IP `192.0.2.30` этого сервера.

Адрес `192.0.2.10` без собственной роли получит синий цвет сервера; служебный `192.0.2.30` — оранжевый цвет своей роли. Фильтр **Role = Management** на вкладке **IP addresses** найдёт служебный адрес.

## 7.5. Удаление

Нажмите **Delete role** в карточке и подтвердите действие. **Серверы, IP-адреса и поддомены сохраняются**, но назначение удалённой роли у них очищается.

После удаления собственной роли IP или поддомена цвет может перейти к роли связанного объекта. Если подходящей роли больше нет, метка исчезнет. DNS-данные от удаления роли не меняются. Чтобы заменить роль, сначала назначьте объектам новую, затем удалите прежнюю: SINVER не переносит назначения автоматически.
