# 8. Хостинги — Hostings

[← Назад](07_Roles_RU.md) · [Содержание](README_RU.md#содержание) · [Вперёд →](09_Zones_RU.md)

Вкладка **Hostings** хранит сведения о поставщиках или площадках, где размещены серверы: название, ссылку, дату оплаты и описание. Один хостинг можно связать с несколькими серверами; у сервера может быть один хостинг или значение `None`.

SINVER использует эти сведения для учёта инфраструктуры. Он не заказывает серверы, не оплачивает услуги и не проверяет состояние договора у поставщика.

## 8.1. Список и поиск

| Столбец | Значение |
| --- | --- |
| **Name** | Название хостинга; ссылка открывает карточку. |
| **URL** | Ссылка на сайт или личный кабинет, открываемая в новой вкладке. |
| **servers** | Количество серверов, которым назначен этот хостинг. Рассчитывается автоматически. |
| **Paid until** | Дата, до которой оплачены услуги. |
| **Description** | Первые 50 символов описания; полное описание доступно в карточке. |

`—` обозначает отсутствующее необязательное значение. Форма поиска содержит:

| Поле | Как работает |
| --- | --- |
| **Name contains** | Поиск по фрагменту названия, например `Example`. |
| **URL contains** | Поиск по фрагменту ссылки. |
| **Paid until** | Поиск по точной дате. Это не диапазон и не фильтр просроченных оплат. |
| **Description contains** | Поиск по фрагменту описания. |
| **Sort by** | Сортировка по `name`, `url`, `paid until` или `description`. По умолчанию — по названию. |

Нажмите **Apply**, чтобы применить заполненные условия одновременно, или **Reset**, чтобы вернуть полный список. Сортировка идёт по возрастанию как по тексту, без учёта регистра латинских букв. Для дат в формате `YYYY-MM-DD` такой порядок совпадает с календарным. Сортировка по количеству серверов не предусмотрена.

## 8.2. Создание хостинга

Заполните форму **Add hosting** и нажмите **Create**.

| Поле | Обязательность и значения | Пример |
| --- | --- | --- |
| **Name** | Обязательно при создании. Уникальное название длиной до 256 символов. | `Example Hosting` |
| **URL** | Необязательно. Полный адрес с протоколом, до 1024 символов. Браузер проверяет формат ссылки. | `https://hosting.example.net/` |
| **Paid until** | Необязательно. Календарная дата; браузер может показывать её в локальном формате, в базе она хранится как `YYYY-MM-DD`. | `2027-12-31` |
| **Description** | Необязательный текст: сведения о площадке, договоре или размещении. | `Площадка приложения; договор INFRA-01` |

**Paid until** относится ко всей записи хостинга. Одна и та же дата выводится для всех связанных серверов на вкладке **Servers**. Отдельные сроки оплаты каждого сервера в этой модели не хранятся. SINVER не отправляет напоминания о продлении.

**Рекомендация:** если у одной компании несколько договоров с разными сроками, заведите отдельную запись для каждого договора, например `Example Hosting / INFRA-01`. Это позволит указывать разные даты без неоднозначности.

## 8.3. Карточка и связь с серверами

В карточке **Hosting: Example Hosting** доступны те же поля. Общий порядок изменения описан в [главе о WEB-интерфейсе](03_Web_Interface_RU.md). Необязательные поля можно очистить; пустые значения сохраняются как отсутствующие.

Раздел **Servers in this hosting** содержит ссылки на связанные серверы, упорядоченные по имени. `—` означает, что связанных серверов нет. Раздел **External link** повторяет сохранённую ссылку и открывает её в новой вкладке.

Чтобы связать `app-01` с площадкой:

1. Создайте запись `Example Hosting`.
2. Откройте карточку `app-01` на вкладке **Servers**.
3. Включите редактирование, выберите **Hosting → Example Hosting** и сохраните сервер.
4. Откройте хостинг и проверьте наличие `app-01` в **Servers in this hosting**. В списке хостингов значение **servers** увеличится на один.

Изменение названия, ссылки или даты оплаты хостинга обновляет сведения для всех связанных серверов. Для переноса сервера на другую площадку измените поле **Hosting** в карточке сервера; сама запись хостинга не перемещает ресурсы между поставщиками.

## 8.4. Удаление и ограничения

**Delete hosting** удаляет запись после подтверждения **Delete hosting?**. Связанные серверы сохраняются, но их поле **Hosting** становится пустым. Их IP-адреса, поддомены и DNS-записи этим действием не изменяются.

SINVER не объединяет одинаковые площадки и не переносит серверы при удалении. Чтобы заменить запись, сначала назначьте серверам другой хостинг.

Названия сохраняются без автоматического удаления пробелов. Повторное название или превышение ограничений длины приводит к отказу сохранения; в текущей версии возможен общий ответ **Internal error**. Серверная проверка формата URL и даты отсутствует: вводите адрес и дату через штатную форму и проверяйте результат в карточке.
