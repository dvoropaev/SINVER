# 5. IP-адреса — IP addresses

[Содержание](README_RU.md) · [Назад: Серверы](04_Servers_RU.MD) · [Далее: Поддомены](06_Subdomains_RU.MD)

Вкладка **IP addresses** (`/ips`) хранит IPv4- и IPv6-адреса серверов. Каждый адрес принадлежит ровно одному серверу и может быть связан с несколькими поддоменами.

**Primary** — основной адрес сервера. При выбранной основной зоне он формирует DNS-запись имени сервера. У сервера может быть **не более одного основного адреса всего**, а не по одному для IPv4 и IPv6. Сервер без основного адреса допустим. Любой адрес, включая дополнительный, можно использовать в [Subdomains](06_Subdomains_RU.MD).

## 5.1. Поля адреса

| Поле интерфейса | Обязательность | Смысл и допустимые значения |
| --- | --- | --- |
| **Type** | Обязательно | `IPv4` или `IPv6`. При создании SINVER проверяет соответствие выбранного типа введённому адресу. |
| **IP** | Обязательно | Один адрес, например `192.0.2.10` или `2001:db8::10`. Не вводите маску сети (`/24`, `/64`), порт или URL. Формат проверяется сервером при создании. Значение уникально во всём справочнике. |
| **Server** | Обязательно | Один существующий сервер. `None` не предусмотрено; сначала создайте карточку сервера. |
| **Role** | Необязательно | Собственная роль адреса из [Roles](07_Roles_RU.MD), например `Public`, либо `None`. |
| **Primary** | Обязательно; по умолчанию `No` | `Yes` — основной адрес; `No` — дополнительный. |

В карточке **Type** и **IP** всегда доступны только для чтения, даже после **Edit**. Изменить можно сервер, роль и признак основного адреса. Для замены адреса создайте новый и перенесите на него связи поддоменов.

IPv6 сохраняется в написании пользователя. Для единообразия используйте сокращённую запись в нижнем регистре, например `2001:db8::10`. Эквивалентные варианты IPv6 приложение не объединяет; см. [текущие проблемы](11_Current_Issues_RU.MD).

## 5.2. Список и фильтры

| Столбец | Что показывает |
| --- | --- |
| **Color** | Цвет собственной роли адреса. Если она не назначена, используется цвет роли его сервера. |
| **Type** | `IPv4` или `IPv6`. |
| **IP** | Адрес; ссылка открывает карточку. |
| **Server** | Имя сервера с основной зоной, если она выбрана. Это текст, не ссылка. |
| **Role** | Только собственная роль адреса; `—`, если не назначена. Наследование цвета не назначает роль. |
| **Primary** | `Primary` для основного адреса; пустая ячейка для дополнительного. |

| Фильтр | Варианты и результат |
| --- | --- |
| **Type** | `Any`, `IPv4`, `IPv6`. |
| **Server** | `Any` либо конкретный сервер. |
| **Role** | `Any` либо собственная роль IP-адреса. Роль сервера в этом фильтре не учитывается. |
| **Primary** | `Any`, `Yes` — основные, `No` — дополнительные. |
| **Sort by** | `ip` — адрес, `type` — версия IP, `server` — короткое имя сервера, `role` — собственная роль, `primary` — сначала дополнительные, затем основные. |

Заполненные фильтры действуют одновременно. Нажмите **Apply** для применения или **Reset** для сброса. По умолчанию список сортируется по `ip`. Адреса сравниваются как текст, поэтому `192.0.2.10` может идти раньше `192.0.2.2`. Текстового поиска по IP нет. Особенность поля сортировки описана в [текущих проблемах](11_Current_Issues_RU.MD).

## 5.3. Добавление и изменение

1. В **Add IP** выберите тип, введите адрес и выберите сервер.
2. При необходимости задайте роль и **Primary**.
3. Нажмите **Create**, затем откройте адрес по ссылке в таблице.
4. Для изменения доступных полей нажмите **Edit**, внесите изменения и нажмите **Save**; см. [общую механику интерфейса](03_Web_Interface_RU.MD).

Если формат неверен, приложение показывает `Invalid IP format.`. Если тип не соответствует адресу — `IP type does not match entered address.`. Адрес при этом не создаётся.

В блоке **Linked subdomains** перечислены поддомены, использующие адрес; ссылки открывают их карточки. При переносе адреса другому серверу эти связи сохраняются. Меняется принадлежность адреса и его участие в автоматической записи имени сервера.

### Безопасная смена основного адреса

**В текущей версии назначение второго основного адреса завершается ошибкой.** Сначала в карточке прежнего основного IP задайте **Primary = No** и сохраните. Затем создайте новый адрес с **Primary = Yes** либо назначьте этот признак существующему. Перед переносом основного IP на другой сервер также проверьте основной адрес у получателя. Причина описана в [текущих проблемах](11_Current_Issues_RU.MD).

## 5.4. Примеры использования

### IPv4 и IPv6 одного сервера

Для `web01` создайте:

| Type | IP | Primary | Назначение |
| --- | --- | --- | --- |
| IPv4 | `192.0.2.10` | `Yes` | Автоматическая A-запись `web01.example.net`. |
| IPv6 | `2001:db8::10` | `No` | AAAA-запись через отдельный поддомен. |

Чтобы имя `web01.example.net` имело также AAAA-запись, создайте поддомен с **Type = AAAA**, **Name = web01**, **Zone = example.net** и свяжите его с `2001:db8::10`.

### Замена адреса без потери имён

При замене `192.0.2.10` на `192.0.2.20` создайте новый адрес с **Primary = No**. В каждом связанном поддомене выберите новый IP вместо старого и сохраните. Если старый IP был основным, смените основной адрес в порядке, описанном выше. После проверки связей удалите старый IP и выполните [синхронизацию DNS](10_DNS_RU.MD).

## 5.5. Удаление

В карточке нажмите **Delete IP** и подтвердите действие.

Удаляется адрес и все его связи с поддоменами. Сервер и поддомены остаются. Если удалён основной IP, новый основной адрес автоматически не выбирается. Если поддомен больше не связан с адресами подходящего типа, он не формирует DNS-запись.

Перед удалением проверьте **Linked subdomains**. Опубликованные данные PowerDNS изменятся только после отдельной синхронизации.
