# 10. DNS — публикация записей

Вкладка **DNS** публикует данные выбранной зоны в PostgreSQL PowerDNS или скачивает файл зоны для BIND9. Изменения на вкладках **Servers**, **IP addresses**, **Subdomains** и **Zones** сами по себе DNS не обновляют.

## 10.1. Какие записи формирует SINVER

| Источник | Результат |
| --- | --- |
| Сервер с **Primary zone** и IP с **Primary = Yes** | `hostname.zone A IPv4` либо `hostname.zone AAAA IPv6` |
| Поддомен `A` со связанными IPv4 | По одной A-записи на каждый подходящий IP |
| Поддомен `AAAA` со связанными IPv6 | По одной AAAA-записи на каждый подходящий IP |
| Поддомен с именем `@` | Запись на имя самой зоны, например `infra.example.net A 192.0.2.10` |
| Параметры зоны | Одна SOA-запись с новым SERIAL |

IP без флага **Primary** публикуется только через явно связанный поддомен. Сервер без основной зоны не создаёт автоматическую запись. Поддомен без IP подходящего семейства не создаёт записи: для A нужны IPv4, для AAAA — IPv6. Роли, цвета, хостинги и описания в DNS не передаются.

У сервера допускается один **Primary** на оба семейства адресов. Для основного имени одновременно с IPv4 и IPv6 создайте поддомен с тем же именем, что и **hostname**, и типом второго семейства. Например, у `app-01` основной IPv4 `192.0.2.10`; поддомен `app-01` типа AAAA со связью на `2001:db8::10` добавит `app-01.infra.example.net AAAA 2001:db8::10`.

Для публикуемых строк PowerDNS установлены `ttl = 3600`, `disabled = False`, `auth = True`. Эти значения нельзя изменить в SINVER. TTL определяет время хранения ответа в DNS-кеше; `disabled` — признак отключённой записи, `auth` — признак авторитетной записи PowerDNS.

> **SINVER управляет всеми A, AAAA и SOA выбранной зоны.** План включает удаление записей этих типов, которых нет в сформированном списке SINVER. Существующие записи других типов, например NS, MX, TXT, CNAME и CAA, сохраняются в PowerDNS. До первой публикации внесите в SINVER все нужные A и AAAA, включая адреса DNS-серверов внутри зоны.

## 10.2. Элементы вкладки

| Элемент | Назначение |
| --- | --- |
| **PowerDNS + PostgreSQL → Zone** | Зона для сравнения и применения изменений PowerDNS |
| **Push** | Чтение PowerDNS и подготовка просмотра; DNS ещё не изменяется |
| **Remote SERIAL** | SERIAL прочитанной SOA в PowerDNS |
| **Local SERIAL** | SERIAL, сохранённый в SQLite SINVER |
| **New SERIAL** | SERIAL, подготовленный для публикации |
| Список изменений, DIFF | Строки `+` будут добавлены, строки `-` удалены |
| **SQL preview** | SQL-операции, соответствующие плану; вручную выполнять их не требуется |
| **Все равно продолжить** | Заново подготовить план при несовпадении локального и удалённого SERIAL |
| **Confirm apply** | Применить план после подтверждения в диалоге браузера |
| **Bind9 → Zone** | Зона для скачивания файла BIND |
| **Generate config** | Скачать файл `<имя_зоны>.db` |

При открытии автоматически выбирается первая зона по имени, если переход не указал конкретную зону. У форм PowerDNS и BIND отдельные списки **Zone**: проверяйте выбор в нужной форме перед действием.

## 10.3. Публикация в PowerDNS

### Условия работы

SINVER подключается непосредственно к базе PostgreSQL; HTTP API PowerDNS не используется. Нужны Python-драйвер `psycopg2`, поля подключения в [карточке зоны](09_Zones_RU.md#93-подключение-к-postgresql) и права пользователя. Подготовка описана в [быстром старте](01_Quick_Start_RU.md).

В таблице `domains` должна существовать строка, где `name` точно равно имени зоны SINVER. Для её `domain_id` в `records` должна быть **ровно одна SOA**. Если зоны нет, SOA отсутствует или их несколько, просмотр остановится с ошибкой. SINVER не создаёт строку `domains` и не исправляет начальную SOA автоматически.

Записи PowerDNS с заглавными буквами в имени или SQL `NULL` в TTL/флагах могут не удалиться; точные дубликаты могут остаться. До первой публикации проверьте эти данные. Объяснение и обход — в [текущих проблемах](11_Current_Issues_RU.md#сравнение-записей-не-исправляет-некоторые-данные-powerdns).

### Порядок отправки

1. Убедитесь, что в SINVER внесены все A и AAAA, которые нужно сохранить в выбранной зоне. Перед первой отправкой сохраните резервную копию базы PowerDNS.
2. Выберите **Zone = infra.example.net** в блоке **PowerDNS + PostgreSQL** и нажмите **Push**.
3. Если SERIAL различаются, появится `Local SERIAL is out of sync with Remote SERIAL.`. Полный DIFF ещё не сформирован. Выясните причину: зону могли изменить другим инструментом или восстановить из копии. Кнопка **Все равно продолжить** повторно читает данные и разрешает подготовку плана, но не применяет его.
4. Сверьте **Remote SERIAL**, **Local SERIAL**, **New SERIAL**, список изменений и **SQL preview**. Особенно внимательно проверьте строки `-`, адреса DNS-серверов и параметры SOA.
5. Нажмите **Confirm apply** и подтвердите **Apply update to PowerDNS?**. Отмена диалога оставляет PostgreSQL без изменений.
6. Дождитесь `PowerDNS update applied and local serial updated.` и проверьте ответы DNS.

**Все равно продолжить** не выполняет слияние и не сохраняет отсутствующие в SINVER записи управляемых типов. Используйте кнопку только после проверки данных выбранной зоны.

Для `app-01` с основной зоной `infra.example.net` и **Primary** IPv4 `192.0.2.10` появится `app-01.infra.example.net A 192.0.2.10`. Если `ns1.infra.example.net` имеет адрес `192.0.2.53`, добавьте его в SINVER отдельным сервером `ns1` с основным адресом или поддоменом A. Иначе существующая A-запись `ns1` попадёт в удаление. Сохранённая NS сама по себе адрес DNS-сервера не защищает.

### Чтение DIFF

Строка имеет формат:

```text
знак name | type | content | ttl | disabled | auth
```

| Часть | Значение |
| --- | --- |
| `+` / `-` | Добавление / удаление строки `records` |
| `name` | Полное DNS-имя; при сравнении SINVER приводит его к нижнему регистру |
| `type` | A, AAAA или SOA |
| `content` | IP либо семь полей SOA: `MNAME RNAME SERIAL REFRESH RETRY EXPIRE MINIMUM` |
| `ttl` | TTL в секундах |
| `disabled` | Признак отключённой записи: `True` / `False` |
| `auth` | Признак авторитетной записи: `True` / `False` |

Например, поддомен `api` типа A, связанный с `192.0.2.10`, добавит:

```text
+ api.infra.example.net | A | 192.0.2.10 | 3600 | False | True
```

SINVER сравнивает имя, тип, содержимое, TTL, `disabled` и `auth`. Изменение любого из этих полей представлено удалением прежней строки и добавлением новой. Поэтому A-запись с TTL `300` заменяется строкой с TTL `3600`, даже если имя и IP прежние. Точные совпадения сохраняются. Другие поля `records` в сравнении не участвуют и при вставке получают значения по умолчанию схемы PowerDNS.

Одинаковые ожидаемые строки из разных источников SINVER объединяются. Если поддомен повторяет основное имя сервера, его адреса добавляются к адресу сервера. Проверьте DIFF, чтобы совпадение имён не направило запросы на лишний сервер.

При изменении SERIAL план обычно удаляет прежнюю SOA и добавляет новую. В **SQL preview** сначала перечислены удаления, затем вставки. Приложение применяет сохранённый план параметризованными запросами; копировать и выполнять текст просмотра вручную не требуется.

> **Неполные данные SINVER могут привести к удалению рабочих записей.** Если у зоны нет подходящих Primary IP и связанных поддоменов, ожидаемый список содержит только SOA. Применение такого плана удаляет существующие A и AAAA. IP неподходящего семейства также может оставить имя без ожидаемой записи.

### Срок действия плана и применение

План хранится в памяти процесса **10 минут**, используется один раз и пропадает после перезапуска SINVER. При сообщении `Preview is expired. Please run push again and confirm apply.` заново нажмите **Push** и проверьте новый план. После ошибки применения также требуется новый просмотр.

При применении SINVER повторно находит зону в `domains` и проверяет её ID. **Он не перепроверяет SERIAL, записи PowerDNS и данные SINVER после просмотра.** Не изменяйте данные между **Push** и **Confirm apply**; после любого изменения создавайте новый просмотр. Согласуйте публикацию с другими пользователями общей базы. Блокировки зоны на время просмотра нет.

Удаления и вставки выполняются в одной транзакции PostgreSQL. Если SQL-запрос завершается ошибкой до фиксации, изменения транзакции откатываются и локальный SERIAL не обновляется. При потере соединения во время фиксации результат может быть неизвестен приложению: сначала проверьте фактические записи PowerDNS, затем готовьте новый план.

Таймаут соединения — 5 секунд. При чтении полного списка записей и применении ограничены отдельный SQL-запрос — 30 секунд, ожидание блокировки — 5 секунд, бездействие в открытой транзакции — 30 секунд. Это не общий предел времени операции. Первичное чтение `domains` и SOA при просмотре не имеет заданного SINVER лимита SQL-запроса.

После фиксации PostgreSQL SINVER создаёт резервную копию SQLite, затем обновляет локальный SERIAL в основной базе SQLite. **Единой транзакции для PostgreSQL и SQLite нет.** Если последняя операция не удалась, PowerDNS уже обновлён. Порядок проверки и восстановления описан ниже.

### Проверка результата

Для локальной установки из быстрого старта запросите записи непосредственно у PowerDNS:

```bash
dig @127.0.0.1 app-01.infra.example.net A +norecurse +noall +answer
dig @127.0.0.1 infra.example.net SOA +norecurse +noall +answer
```

Ожидаемые ответы после публикации:

```text
app-01.infra.example.net. 3600 IN A 192.0.2.10
infra.example.net. 3600 IN SOA ns1.infra.example.net. hostmaster.infra.example.net. 2610071530 3600 600 1209600 300
```

Для удалённого PowerDNS укажите его доступный адрес вместо `127.0.0.1`. Фактический SERIAL должен совпадать с **New SERIAL** применённого плана и значением карточки зоны. При публикации AAAA аналогично запросите запись нужного имени с типом AAAA.

SINVER не очищает кеш PowerDNS и не отправляет уведомления вторичным серверам. Если в базе уже новые данные, а DNS возвращает прежние, проверьте кеш и конфигурацию репликации PowerDNS. Сообщение об успехе подтверждает выполнение запросов приложения; после него всё равно проверьте SOA и адресные записи.

### Резервная копия и восстановление

Автоматические копии SINVER содержат SQLite, но **не базу PowerDNS**. Для неё требуется отдельное резервирование. На хосте PostgreSQL перед первой отправкой сохраните архив в каталоге резервных копий:

```bash
umask 0077
sudo -u postgres pg_dump --format=custom powerdns > powerdns-before-sinver.dump
```

`umask` ограничивает доступ к новому файлу владельцем. `pg_dump` читает базу `powerdns` и записывает архив в формате custom. Архив содержит все зоны этой базы; восстановление всего архива затронет их все.

Если применён неправильный план, кнопки отмены нет. Восстановите записи средствами PostgreSQL/PowerDNS из проверенной копии либо исправьте данные SINVER и подготовьте новый план. **При возврате старых DNS-данных назначьте SOA номер, который вторичные серверы примут как более новый.** Восстановление прежнего SERIAL само по себе не обеспечивает обновление вторичных серверов.

Если PostgreSQL обновился, а локальный SERIAL не сохранился, сначала проверьте фактические записи и SOA PowerDNS. Устраните ошибку записи или резервного копирования SQLite, затем укажите фактический SERIAL в карточке зоны SINVER. Не повторяйте принудительную отправку до проверки обеих баз.

### Частые сообщения

| Сообщение | Действие |
| --- | --- |
| `psycopg2 is not installed` | Установите драйвер PostgreSQL в Python-окружение, которым запускается SINVER |
| `PostgreSQL connection data is incomplete` | Заполните адрес PostgreSQL и пользователя в карточке зоны |
| `Domain … not found in PowerDNS` | Создайте зону PowerDNS и проверьте совпадение имени с **Zone** |
| `Expected exactly 1 SOA record …` | Исправьте отсутствующую или дублирующуюся SOA PowerDNS |
| `Local SERIAL is out of sync with Remote SERIAL.` | Сверьте действующую зону с данными SINVER, затем согласуйте SERIAL или продолжите подготовку после проверки |
| `Preview is expired. Please run push again and confirm apply.` | Заново нажмите **Push** и проверьте новый план |
| `PowerDNS apply failed: …` | Проверьте PostgreSQL, права, блокировки и текст ошибки. Если результат фиксации неизвестен, сначала проверьте фактическую зону; затем создайте новый план |

## 10.4. SERIAL

SINVER генерирует SERIAL при подготовке просмотра PowerDNS или файла BIND в формате `YYMMDDhhmm`: год из двух цифр, месяц, день, час и минута. Время берётся **в локальном часовом поясе хоста SINVER**. Например, `2610071530` означает 7 октября 2026 года, 15:30 по времени этого хоста.

При успешном применении PowerDNS SERIAL сохраняется в SQLite. При просмотре, отказе от подтверждения и экспорте BIND локальное значение не меняется.

> **Генератор не гарантирует увеличение SERIAL.** Две публикации за одну минуту могут получить одинаковый номер. После изменения часов или при большем удалённом номере новый SERIAL может оказаться меньше. Перед применением сверяйте **New SERIAL** с **Remote SERIAL**, особенно для зон со вторичными DNS-серверами: они могут не забрать изменение с прежним или меньшим номером. Обход описан в [текущих проблемах](11_Current_Issues_RU.md#serial-не-всегда-увеличивается).

## 10.5. Экспорт BIND9

1. Выберите зону в блоке **Bind9**.
2. Нажмите **Generate config**. Браузер скачает, например, `infra.example.net.db`.
3. Проверьте и дополните файл, затем установите его на BIND9 вручную.

Это **файл записей зоны**, а не полная конфигурация службы. Он содержит `$TTL 3600`, SOA с новым SERIAL и сформированные A/AAAA. Подключение к PostgreSQL не требуется. **SERIAL в SQLite при экспорте не меняется.**

Пример файла для основного имени `app-01` и двух поддоменов `api`:

```bind
$TTL 3600
@ IN SOA ns1.infra.example.net. hostmaster.infra.example.net. (2610071530 3600 600 1209600 300)
api.infra.example.net. IN A 192.0.2.10
api.infra.example.net. IN AAAA 2001:db8::10
app-01.infra.example.net. IN A 192.0.2.10
```

Имена A/AAAA записываются полностью с завершающей точкой. Файл не содержит `$ORIGIN`: имя зоны передаёт конфигурация BIND или аргумент утилиты проверки.

**Экспорт не добавляет NS, MX, TXT, CNAME и другие типы записей.** Для полноценной зоны нужны как минимум NS; если DNS-сервер находится внутри зоны, добавьте его адресные записи. Например:

```bind
@ IN NS ns1.infra.example.net.
ns1.infra.example.net. IN A 192.0.2.53
```

При обновлении существующей зоны перенесите в новый файл необходимые записи других типов и настройки. Полная замена прежнего файла только экспортом SINVER потеряет эти записи.

Перед установкой также проверьте полные MNAME/RNAME с завершающей точкой и увеличение SERIAL относительно опубликованной зоны. Для проверки синтаксиса установите утилиты BIND на Debian:

```bash
sudo apt install bind9-utils
```

Проверьте дополненный файл:

```bash
named-checkzone infra.example.net ./infra.example.net.db
```

Ожидаемый результат:

```text
zone infra.example.net/IN: loaded serial 2610071530
OK
```

Если проверка сообщает `has no NS records`, файл ещё не готов к публикации. Успешная проверка синтаксиса не подтверждает доступность DNS-сервера или делегирование.

Установите файл в путь зоны из конфигурации BIND, проверьте владельца и права, выполните `rndc reload infra.example.net` и проверьте SOA и адресные записи через `dig`. SINVER не изменяет `named.conf`, не переносит файл и не перезагружает BIND. После отдельной публикации на BIND и возвращения к PowerDNS сверяйте состояние зон и SERIAL.
