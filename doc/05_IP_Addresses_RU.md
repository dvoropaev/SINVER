# 5. IP-адреса — IP addresses

[← Назад](04_Servers_RU.md) · [Содержание](README_RU.md#содержание) · [Вперёд →](06_Subdomains_RU.md)

Вкладка **IP addresses** хранит IPv4- и IPv6-адреса серверов. Каждый адрес принадлежит ровно одному серверу и может быть связан с несколькими поддоменами. SINVER ведёт учёт адресов; настройку сетевых интерфейсов выполняет администратор сервера.

Правила работы с формами и кнопками описаны в [главе о веб-интерфейсе](03_Web_Interface_RU.md).

## Список адресов

| Столбец | Что показывает |
| --- | --- |
| **Color** | Цвет собственной роли адреса. Если роль адреса отсутствует, используется цвет роли его сервера. Если обе роли отсутствуют, индикатор не отображается. |
| **Type** | Семейство адреса: `IPv4` или `IPv6`. |
| **IP** | IP-адрес; ссылка открывает его карточку. |
| **Server** | Имя сервера с основной зоной, если она назначена: например `app-01.infra.example.net`. |
| **Role** | Роль, назначенная непосредственно адресу. При отсутствии отображается `—`, даже если цвет получен от роли сервера. |
| **Primary** | Надпись `Primary` у основного адреса; у остальных ячейка пустая. |

### Фильтры и сортировка

| Поле | Значения и действие |
| --- | --- |
| **Type** | `Any` — оба семейства; `IPv4` или `IPv6` — только выбранное семейство. |
| **Server** | `Any` — все серверы; имя сервера — только его адреса. В выпадающем списке имя указано без зоны. |
| **Role** | `Any` — все роли; название роли — адреса с этой собственной ролью. Роль сервера при фильтрации не учитывается. |
| **Primary** | `Any` — все адреса; `Yes` — основные; `No` — остальные. |
| **Sort by** | `ip` — по строке адреса; `type` — по семейству; `server` — по имени сервера без зоны; `role` — по собственной роли; `primary` — сначала обычные адреса, затем основные. |

Фильтры действуют одновременно. Например, **Server** = `app-01` и **Type** = `IPv6` покажут IPv6-адреса одного сервера. Сортировка выполняется по возрастанию, по умолчанию — `ip`. Адреса сортируются как текст: `192.0.2.100` может стоять раньше `192.0.2.20`.

## Добавление адреса

Сначала создайте [сервер](04_Servers_RU.md), затем заполните форму **Add IP**.

| Поле | Назначение, значения и ограничения | Пример |
| --- | --- | --- |
| **Type** | `IPv4` или `IPv6`; по умолчанию `IPv4`. Семейство должно соответствовать введённому адресу. | `IPv4` |
| **IP** | Обязательный адрес в допустимом формате выбранного семейства. Вводите один адрес без маски сети, порта или схемы URL. Одинаковая строка адреса может присутствовать в SINVER только один раз. | `192.0.2.10` или `2001:db8::10` |
| **Server** | Обязательный существующий сервер. Адрес будет принадлежать ему. | `app-01` |
| **Role** | Необязательная роль из [Roles](07_Roles_RU.md). `None` — собственная роль отсутствует; цвет может быть получен от сервера. | `public` |
| **Primary** | `No` — обычный адрес; `Yes` — основной адрес сервера. По умолчанию `No`. | `Yes` для `192.0.2.10` |

При неверном формате SINVER показывает **Invalid IP format.** При несовпадении семейства — **IP type does not match entered address.** Исправьте данные и повторите создание.

Для IPv6 используйте единый сокращённый формат с буквами в нижнем регистре, например `2001:db8::10`. SINVER сохраняет введённую строку: эквивалентные варианты записи IPv6 могут ошибочно учитываться как разные адреса. Подробнее — в [главе о текущих проблемах](11_Current_Issues_RU.md).

## Основной адрес и DNS

Основной адрес используется для автоматической записи имени сервера в его **Primary zone**:

| Основной адрес сервера `app-01` | Запись для зоны `infra.example.net` |
| --- | --- |
| `192.0.2.10`, `IPv4` | `app-01.infra.example.net. IN A 192.0.2.10` |
| `2001:db8::10`, `IPv6` | `app-01.infra.example.net. IN AAAA 2001:db8::10` |
| Основной адрес отсутствует | Автоматическая запись имени сервера не создаётся. |

> **Важно:** у сервера допускается один основной IP на оба семейства, а не по одному IPv4 и IPv6. Первый добавленный адрес автоматически основным не становится. Для публикации обоих семейств используйте отдельные записи `A` и `AAAA` во вкладке [Subdomains](06_Subdomains_RU.md).

Адрес с **Primary** = `No` также может участвовать в DNS через связанную запись поддомена. Подробности построения и синхронизации записей — в [главе DNS](10_DNS_RU.md).

### Замена основного адреса

В текущей версии назначение нового основного IP при существующем основном адресе приводит к ошибке. Используйте следующий порядок:

1. Откройте карточку текущего основного адреса.
2. Переведите **Primary** в `No` и сохраните.
3. Откройте карточку нужного адреса, установите **Primary** = `Yes` и сохраните. Новый адрес также можно создать сразу с `Yes`, если основной ещё не назначен.
4. Проверьте **Primary IP** в списке **Servers**.

Между шагами 2 и 3 сервер временно не имеет основного адреса. Выполняйте синхронизацию DNS после завершения замены.

## Карточка адреса и изменение связей

В карточке доступны поля из формы добавления, но **Type** и **IP** всегда доступны только для чтения. Через **Edit** можно изменить **Server**, **Role** и **Primary**.

Блок **Linked subdomains** показывает все записи поддоменов, связанные с адресом. Ссылки открывают соответствующие карточки, где можно изменить набор **Linked IP addresses**.

Возможные сценарии:

- **Перенос учётной записи адреса на другой сервер:** измените **Server**. Связи с поддоменами сохранятся, а сведения о связанных серверах и унаследованный цвет обновятся. Если адрес основной, предварительно убедитесь, что у целевого сервера нет другого основного адреса.
- **Отдельное обозначение назначения адреса:** назначьте **Role**, например `public`, сохранив для сервера роль `application`. Индикатор адреса получит цвет `public`.
- **Исправление IP или семейства:** создайте запись с правильными данными, перенесите нужные связи в карточках поддоменов, затем удалите ошибочную запись. При замене основного адреса соблюдайте порядок из предыдущего раздела.

## Удаление адреса

**Delete IP** в карточке запрашивает подтверждение. После удаления исчезают сам адрес и все его связи с поддоменами. Сервер и записи поддоменов сохраняются.

Если удалён основной адрес, новый автоматически не выбирается. Если поддомен был связан только с удалённым адресом, для него больше не будет сформировано записи DNS. Перед удалением проверьте **Linked subdomains** и при необходимости назначьте замену.
