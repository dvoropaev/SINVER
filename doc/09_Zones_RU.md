# 9. DNS-зоны — Zones

[← Назад](08_Hostings_RU.md) · [Содержание](README_RU.md#содержание) · [Вперёд →](10_DNS_RU.md)

Вкладка **Zones** задаёт DNS-зоны, параметры их записи SOA и подключения к базе PostgreSQL, которую использует PowerDNS. Зона объединяет DNS-имена: для зоны `infra.example.net` имя сервера `app-01` образует адрес `app-01.infra.example.net`.

**Создание зоны в SINVER сохраняет её в локальной SQLite.** Оно не создаёт зону в PowerDNS и не публикует DNS-записи. Для отправки сведений используйте [вкладку DNS](10_DNS_RU.md). В PowerDNS соответствующая зона должна быть создана заранее.

## 9.1. Список, фильтры и сортировка

В таблице есть столбцы **Zone**, **MNAME**, **RNAME**, **SERIAL**, **REFRESH**, **RETRY**, **EXPIRE**, **MINIMUM**, **psql address**, **psql user**, **Description**. Их значения описаны ниже в таблицах полей. Название зоны открывает карточку. Описание сокращается до первых 50 символов; необязательные пустые значения отображаются как `—`.

Для каждого столбца есть текстовый фильтр с подписью **contains**: **Zone contains**, **MNAME contains**, **RNAME contains**, **SERIAL contains**, **REFRESH contains**, **RETRY contains**, **EXPIRE contains**, **MINIMUM contains**, **psql address contains**, **psql user contains**, **Description contains**. Каждый ищет фрагмент соответствующего значения. Все заполненные условия действуют одновременно.

**Sort by** позволяет выбрать любое из этих 11 полей. По умолчанию список упорядочен по зоне. **Apply** применяет поиск и сортировку; **Reset** возвращает полный список с сортировкой по зоне.

Сортировка идёт по возрастанию как по тексту, без учёта регистра латинских букв. Даже SOA-интервалы сортируются как строки: `100` окажется перед `20`. Числового сравнения и поиска по диапазонам нет. Имя базы и пароль в таблице не показаны, фильтров для них нет.

## 9.2. Поля зоны и SOA

SOA (*Start of Authority*) — служебная DNS-запись с информацией об ответственном сервере, администраторе и параметрах обновления зоны. В форме **Add zone** все восемь полей следующей таблицы обязательны.

| Поле создания → поле карточки | Назначение и значения | Пример |
| --- | --- | --- |
| **Zone → zone** | Имя DNS-зоны. Уникально в SINVER, максимум 255 символов. Укажите доменное имя без протокола, пути и завершающей точки; оно должно совпадать с именем зоны в PowerDNS. | `infra.example.net` |
| **MNAME → mname** | Полное DNS-имя основного авторитетного сервера зоны с завершающей точкой. Само поле не создаёт запись NS и не настраивает делегирование. | `ns1.infra.example.net.` |
| **RNAME → rname** | Адрес администратора в формате SOA: первая точка заменяет `@`; завершающая точка обозначает полное имя. Для почты `hostmaster@infra.example.net` укажите значение справа. | `hostmaster.infra.example.net.` |
| **SERIAL → serial** | Номер версии зоны. Перед первой синхронизацией укажите текущий SERIAL из SOA PowerDNS; SINVER сравнивает его с локальным значением. | `2610071200` |
| **REFRESH → refresh** | Интервал в секундах, через который вторичные DNS-серверы проверяют обновления зоны. | `3600` — 1 час |
| **RETRY → retry** | Интервал в секундах до повторной попытки обновления после неудачи. | `600` — 10 минут |
| **EXPIRE → expire** | Время в секундах, после которого вторичный DNS-сервер перестаёт обслуживать зону, если не может обновить её с основного. | `1209600` — 14 дней |
| **MINIMUM → minimum** | Значение SOA для времени кеширования отрицательных DNS-ответов, например ответа об отсутствии имени. Оно не задаёт TTL обычных A/AAAA-записей в SINVER. | `300` — 5 минут |

Пример полной SOA для этих значений:

```text
ns1.infra.example.net. hostmaster.infra.example.net. 2610071200 3600 600 1209600 300
```

Это содержимое одной записи SOA, а не команда. Значения интервалов — пример для учебной зоны; администратор DNS выбирает их с учётом требований к обновлению и отказоустойчивости.

**Рекомендация:** записывайте SERIAL и интервалы целыми неотрицательными числами, а MNAME и RNAME — полными DNS-именами с завершающей точкой. Точка нужна, чтобы при экспорте BIND эти имена не считались относительными. Для SERIAL допустим диапазон 32-битного беззнакового числа `0…4294967295`. SINVER хранит эти поля как текст и не проверяет числовой диапазон, корректность DNS-имён или соотношение интервалов; подробнее см. [текущие проблемы](11_Current_Issues_RU.md).

При применении изменений к PowerDNS SINVER создаёт новый SERIAL по локальному времени процесса в формате `YYMMDDHHMM`, затем сохраняет его в SQLite. **В течение одной минуты SERIAL может повториться; автоматическое увеличение относительно предыдущего значения не гарантируется.** Поведение предварительного просмотра и отправки описано в [главе DNS](10_DNS_RU.md).

## 9.3. Подключение к PostgreSQL

Эти поля необязательны для локального учёта зоны и экспорта файла. Для синхронизации с PowerDNS обязательно задайте адрес PostgreSQL и пользователя; остальные параметры должны позволять реально подключиться к базе.

| Поле создания → поле карточки | Как используется | Пример |
| --- | --- | --- |
| **PostgreSQL address → psql_address** | Передаётся драйверу PostgreSQL как `host`. Это имя узла, IP-адрес либо каталог Unix-сокета; максимум 256 символов. Вводите адрес без `http://`, без имени базы и без `:порт`. | `127.0.0.1` или `/var/run/postgresql` |
| **DB name → db_name** | Имя базы с таблицами PowerDNS. Если поле пустое, SINVER подключается к базе `powerdns`. Максимум 256 символов. | `powerdns` |
| **PostgreSQL user → psql_user** | Учётная запись PostgreSQL для чтения зоны и изменения записей PowerDNS. Максимум 256 символов. | `sinver_dns` |
| **PostgreSQL password → psql_password** | Пароль этой учётной записи, максимум 256 символов. При создании пустое поле означает отсутствие сохранённого пароля; драйвер получает пустую строку. | Пароль, заданный при настройке PostgreSQL |
| **Description → Description** | Необязательные сведения о назначении зоны. | `Серверы инфраструктуры приложения` |

Обычное подключение использует стандартный порт PostgreSQL `5432`. SINVER не передаёт отдельные параметры `port` и `sslmode`; на их значения могут влиять настройки клиентской библиотеки PostgreSQL и окружение процесса. В частности, `psql_address` не является строкой подключения: значение `127.0.0.1:5432` не разбирается на узел и порт. Для защищённого подключения настройте PostgreSQL и его клиентское окружение; одного заполнения формы для этого недостаточно.

Для установления соединения задан таймаут 5 секунд. В операциях чтения полного списка записей и применения изменений также используются ограничения: выполнение запроса — 30 секунд, ожидание блокировки — 5 секунд, бездействие в открытой транзакции — 30 секунд.

> **Пароль хранится открытым текстом в SQLite и попадает в её резервные копии.** Ограничьте права доступа к файлу базы и каталогу копий; учётной записи PostgreSQL выдайте только права, необходимые для работы с PowerDNS. Не включайте пароли в описание зоны.

## 9.4. Создание и редактирование

1. В **Add zone** заполните **Zone** и семь параметров SOA.
2. Если планируется синхронизация, задайте параметры PostgreSQL для уже существующей зоны PowerDNS.
3. Нажмите **Create**. Сообщение **Zone created.** подтверждает сохранение в SINVER, но не проверку подключения.
4. Откройте карточку зоны. Кнопка **Go to DNS tab** переводит на DNS с выбранной зоной, где можно подготовить предварительный просмотр изменений.

В карточке поля подписаны внутренними именами `zone`, `mname`, `rname` и так далее; соответствие показано в таблицах выше. Общий порядок редактирования описан в [главе о WEB-интерфейсе](03_Web_Interface_RU.md).

Поле **psql_password** всегда отображается пустым с подсказкой **Leave empty to keep unchanged**. При сохранении:

| Что введено | Результат |
| --- | --- |
| Пустая строка | Ранее сохранённый пароль остаётся без изменения. |
| Новый непустой пароль | Сохранённый пароль заменяется. |

**Очистить ранее сохранённый пароль через обычную форму нельзя.** Остальные необязательные поля, включая адрес, базу, пользователя и описание, можно очистить. После очистки адреса или пользователя синхронизация будет недоступна.

При создании браузер требует значения SOA, но при редактировании обязательность не задана. Текущая версия допускает сохранение пустых SOA-полей и не проверяет их формат. Перед нажатием **Save** самостоятельно проверьте все восемь основных полей. Повторное имя зоны и превышение ограничений длины не сохранятся; возможен общий ответ **Internal error**.

### Сценарий: основная зона сервера

Создайте `infra.example.net`, затем выберите её в поле **Primary zone** сервера `app-01`. При наличии основного IP-адреса SINVER подготовит A- или AAAA-запись для `app-01.infra.example.net`. Дополнительное имя, например `api.infra.example.net`, задаётся на вкладке [Subdomains](06_Subdomains_RU.md).

Переименование зоны меняет имена, которые SINVER формирует для связанных серверов и поддоменов. Зона в PowerDNS автоматически не переименовывается: синхронизация будет искать новое имя в таблице `domains`. Проверяйте эти связи перед изменением **zone**.

## 9.5. Удаление зоны

Кнопка **Delete zone** запрашивает подтверждение **Delete zone?**.

- Если хотя бы у одного сервера зона выбрана как **Primary zone**, удаление запрещено базой данных. Сначала выберите для этих серверов другую основную зону или `None`. Текущая версия может сообщить об отказе как **Internal error**.
- Если таких серверов нет, удаление зоны также удаляет все её поддомены и их связи с IP-адресами. Сами серверы и IP-адреса сохраняются.
- Зона и записи в PowerDNS этим действием не удаляются.

**Перед удалением проверьте поддомены зоны и сохраните необходимые сведения.** Если зона больше не должна обслуживаться DNS, отдельно выполните соответствующее изменение в PowerDNS.
