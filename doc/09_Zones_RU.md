# 9. DNS-зоны — Zones

Вкладка **Zones** хранит параметры DNS-зон, их SOA-записей и подключения к PostgreSQL, который использует PowerDNS. Зона объединяет DNS-имена: для зоны `infra.example.net` имя сервера `app-01` образует `app-01.infra.example.net`.

**Создание или изменение зоны в SINVER не изменяет DNS-сервер.** Публикация выполняется отдельно на вкладке [DNS](10_DNS_RU.md). Саму зону в PowerDNS нужно создать заранее.

Общие действия с формами описаны в главе [о веб-интерфейсе](03_Web_Interface_RU.md).

## 9.1. Список, фильтры и сортировка

Таблица содержит имя зоны, семь параметров SOA, адрес PostgreSQL, пользователя PostgreSQL и описание. Нажмите имя зоны, чтобы открыть карточку. В списке описание сокращается до первых 50 символов; полное описание доступно в карточке. Необязательные пустые значения отображаются как `—`. Имя базы и пароль PostgreSQL в таблице не показаны.

Каждый фильтр с окончанием **contains** ищет часть значения:

| Фильтр | Где выполняется поиск |
| --- | --- |
| **Zone contains** | Имя зоны |
| **MNAME contains** | Имя основного DNS-сервера |
| **RNAME contains** | Контакт администратора в формате SOA |
| **SERIAL contains** | Серийный номер зоны |
| **REFRESH contains** | Интервал проверки обновлений |
| **RETRY contains** | Интервал повторного обращения |
| **EXPIRE contains** | Срок действия данных вторичного сервера |
| **MINIMUM contains** | Параметр отрицательного кеширования |
| **psql address contains** | Адрес PostgreSQL |
| **psql user contains** | Пользователь PostgreSQL |
| **Description contains** | Полное описание зоны |

Непустые фильтры действуют одновременно. Например, **Zone contains = example** и **psql user contains = sinver** найдут зоны с обоими совпадениями. Числовые параметры тоже фильтруются как текст: **REFRESH contains = 60** найдёт `60`, `600` и `3600`. Символы `%` и `_` работают как шаблоны SQL LIKE: любое число символов и один символ соответственно.

**Sort by** сортирует по одному из этих 11 полей по возрастанию, без учёта регистра латинских букв. Параметры SOA хранятся как текст: `100` окажется перед `20`. Числового сравнения и поиска по диапазонам нет. По умолчанию зоны отсортированы по имени. Нажмите **Apply**, чтобы применить фильтры и сортировку, или **Reset**, чтобы вернуть полный список с сортировкой по имени зоны.

## 9.2. Поля зоны и SOA

SOA (*Start of Authority*) — служебная DNS-запись со сведениями об основном DNS-сервере, контакте администратора и параметрах обновления зоны. В форме **Add zone** обязательны **Zone** и все семь параметров SOA.

| Поле создания → поле карточки | Назначение и требования | Пример |
| --- | --- | --- |
| **Zone → zone** | Уникальное имя зоны, до 255 символов. Укажите без протокола, пути и завершающей точки; оно должно точно совпадать с `domains.name` в PowerDNS | `infra.example.net` |
| **MNAME → mname** | Полное имя основного авторитетного DNS-сервера с завершающей точкой. Это поле не создаёт NS и не настраивает делегирование | `ns1.infra.example.net.` |
| **RNAME → rname** | Контакт администратора в формате SOA: точка заменяет `@` в почтовом адресе, завершающая точка обозначает полное имя | `hostmaster.infra.example.net.` для `hostmaster@infra.example.net` |
| **SERIAL → serial** | Текущий номер версии SOA: целое десятичное число от `0` до `4294967295`. Перед первой синхронизацией скопируйте его из SOA PowerDNS | `2610071200` |
| **REFRESH → refresh** | Через сколько секунд вторичные DNS-серверы проверяют обновление зоны | `3600` — 1 час |
| **RETRY → retry** | Через сколько секунд повторяют неудачную попытку обновления | `600` — 10 минут |
| **EXPIRE → expire** | Через сколько секунд без успешного обновления вторичный сервер перестаёт обслуживать зону | `1209600` — 14 дней |
| **MINIMUM → minimum** | Параметр времени кеширования отрицательных DNS-ответов, например об отсутствии имени | `300` — 5 минут |

Полная SOA с такими значениями:

```text
ns1.infra.example.net. hostmaster.infra.example.net. 2610071200 3600 600 1209600 300
```

Вводите SERIAL и интервалы целыми неотрицательными десятичными числами. SINVER хранит их как текст и не проверяет числовой формат, диапазон SERIAL, корректность DNS-имён или соотношение интервалов. Перед сохранением проверьте значения самостоятельно; известные ограничения описаны в [текущих проблемах](11_Current_Issues_RU.md).

В MNAME и RNAME используйте полные имена с завершающей точкой: экспорт BIND вставляет значения без изменения, и точка предотвращает повторное добавление имени зоны. В RNAME нельзя вводить обычный почтовый адрес с `@`. Если часть адреса до `@` содержит точку, её экранируют обратной косой чертой: `dns\.admin.infra.example.net.` для `dns.admin@infra.example.net`.

MINIMUM **не задаёт TTL записей A и AAAA**: при публикации SINVER использует TTL `3600` секунд. Новый SERIAL генерируется по локальному времени хоста в формате `YYMMDDHHMM`; после успешного применения PowerDNS он сохраняется в SQLite. **Автоматическое увеличение относительно прежнего значения не гарантируется.** Подробности — в [главе DNS](10_DNS_RU.md#104-serial).

## 9.3. Подключение к PostgreSQL

Эти поля необязательны для локального учёта зоны и экспорта BIND. Для PowerDNS задайте адрес PostgreSQL и пользователя; остальные параметры должны позволять подключиться к базе.

| Поле создания → поле карточки | Как используется | Пример |
| --- | --- | --- |
| **PostgreSQL address → psql_address** | Передаётся драйверу как `host`: имя узла, IPv4/IPv6-адрес либо абсолютный путь к каталогу Unix-сокета. До 256 символов. Вводите без `http://`, имени базы и суффикса `:порт` | `127.0.0.1` или `/var/run/postgresql` |
| **DB name → db_name** | Имя базы с таблицами PowerDNS, до 256 символов. Если поле пустое, используется `powerdns` | `powerdns` |
| **PostgreSQL user → psql_user** | Учётная запись с правами чтения `domains` и `records`, добавления и удаления строк `records`, получения значений последовательности ID записей. До 256 символов; пример настройки прав — в [быстром старте](01_Quick_Start_RU.md) | `sinver_writer` |
| **PostgreSQL password → psql_password** | Пароль учётной записи, до 256 символов. При создании пустое поле означает пустой пароль подключения | Пароль, заданный при настройке PostgreSQL |
| **Description → Description** | Необязательное описание зоны; разрешены несколько строк. Ограничение длины в текущей схеме не установлено | `Серверы инфраструктуры приложения` |

Отдельных полей порта и SSL нет. SINVER не передаёт драйверу параметры `port` и `sslmode`; на них влияют настройки клиентской библиотеки PostgreSQL и окружение процесса. Обычно используется порт `5432`. Значение `127.0.0.1:5433` в **psql_address** не разбирается на узел и порт. Для защищённого подключения настройте PostgreSQL и его клиентское окружение.

Для установления соединения задан таймаут 5 секунд. При чтении полного списка записей и применении изменений ограничены выполнение отдельного запроса — 30 секунд, ожидание блокировки — 5 секунд, бездействие в открытой транзакции — 30 секунд. Первичное чтение зоны и SOA при подготовке просмотра не имеет заданного SINVER лимита SQL-запроса.

## 9.4. Создание и редактирование

1. В **Add zone** заполните **Zone** и семь параметров SOA.
2. Для синхронизации задайте параметры PostgreSQL уже существующей зоны PowerDNS.
3. Нажмите **Create**. Сообщение **Zone created.** подтверждает сохранение в SINVER; подключение пока не проверено.
4. Откройте карточку зоны. Для изменения нажмите **Edit**, исправьте поля и нажмите **Save**.
5. Кнопка **Go to DNS tab** переводит на вкладку DNS с выбранной зоной, где можно подготовить просмотр изменений.

Поле **psql_password** всегда отображается пустым с подсказкой **Leave empty to keep unchanged**; сохранённый пароль браузеру не передаётся.

| Что введено при Save | Результат |
| --- | --- |
| Пустая строка | Прежний пароль остаётся без изменения |
| Новый непустой пароль | Сохранённый пароль заменяется |

**Очистить сохранённый пароль штатной формой нельзя.** Остальные необязательные поля можно очистить. После очистки адреса или пользователя синхронизация будет недоступна.

При создании браузер требует значения SOA, но при редактировании обязательность не задана. Текущая версия допускает пустые SOA-поля и не проверяет их формат. Перед **Save** проверьте все восемь основных полей. Повторное имя зоны и превышение ограничений длины не сохранятся; возможен общий ответ **Internal error**.

### Пример: основная зона первого сервера

1. Создайте в PowerDNS `infra.example.net` с SOA и NS по [инструкции быстрого старта](01_Quick_Start_RU.md).
2. Добавьте эту зону в SINVER. Укажите фактический SERIAL существующей SOA и параметры подключения PostgreSQL.
3. Создайте сервер `app-01` и выберите `infra.example.net` в **Primary zone**.
4. Добавьте серверу IPv4 `192.0.2.10` с **Primary = Yes**. При публикации SINVER сформирует `app-01.infra.example.net A 192.0.2.10`.

Для дополнительного имени `api.infra.example.net` создайте поддомен `api` и свяжите его с нужными IP; порядок описан в главе [«Поддомены»](06_Subdomains_RU.md).

Переименование зоны меняет имена, которые SINVER формирует для связанных серверов и поддоменов. Зона PowerDNS автоматически не переименовывается, а записи под прежним именем не удаляются. До публикации проверьте, что зона с новым именем существует в `domains` и для неё заданы правильные параметры подключения.

## 9.5. Удаление зоны

Кнопка **Delete zone** запрашивает подтверждение **Delete zone?**.

- Если хотя бы один сервер использует зону как **Primary zone**, SQLite запрещает удаление. Сначала выберите для этих серверов другую зону или `None`. Текущая версия может сообщить об отказе как **Internal error**.
- Если зона не назначена основной ни одному серверу, её удаление также удаляет все её поддомены и их связи с IP. Сами серверы, IP, роли и хостинги сохраняются.
- Зона и записи в PowerDNS или BIND этим действием не удаляются. Их удаление выполните отдельно средствами DNS-сервера.

**Перед удалением проверьте поддомены зоны и сохраните необходимые сведения.**
