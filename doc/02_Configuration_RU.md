# 2. Конфигурация

## Конфигурационный файл

Правильное имя файла — **`sinver.toml`**. SINVER читает настройки при запуске. После установки через `make install` используется `/etc/sinver.toml`; повторная установка сохраняет существующий файл.

Формат — TOML: строки заключаются в кавычки, целые числа записываются без кавычек. Все параметры расположены в корне файла, без секций.

```toml
database_path = "/var/lib/sinver/sinver.sqlite"
database_backup_path = "/var/lib/sinver/backups"
http_addr = "127.0.0.1"
http_port = 8080
log_file = "/var/log/sinver/sinver.log"
```

| Параметр | Тип и допустимое значение | Назначение | Значение в поставляемом файле |
|---|---|---|---|
| `database_path` | Непустая строка: путь к файлу SQLite | Инвентарная база SINVER: серверы, IP-адреса, справочники, зоны и параметры подключения к PostgreSQL | `/var/lib/sinver/sinver.sqlite` |
| `database_backup_path` | Непустая строка: путь к каталогу | Резервные копии SQLite перед изменением данных и миграцией схемы | `/var/lib/sinver/backups` |
| `http_addr` | Непустая строка: адрес прослушивания | Сетевой интерфейс встроенного HTTP-сервера | `127.0.0.1` |
| `http_port` | Целое число от `1` до `65535` | Порт встроенного HTTP-сервера | `8080` |
| `log_file` | Непустая строка: путь к файлу | Журнал приложения | `/var/log/sinver/sinver.log` |

**`database_path`, `database_backup_path` и `log_file` обязательны**: значений по умолчанию для них нет. Если не указать `http_addr` или `http_port`, SINVER использует `127.0.0.1` и `8080` соответственно. Неизвестные ключи игнорируются, поэтому проверяйте написание параметров.

Пароли и адрес PostgreSQL задаются для каждой зоны во вкладке [Zones](09_Zones_RU.md), а не в TOML. База SQLite и PostgreSQL выполняют разные задачи: SQLite хранит инвентаризацию SINVER, PostgreSQL — данные PowerDNS.

### Как вычисляются пути

- Абсолютный путь используется как есть.
- Относительный путь отсчитывается от каталога конфигурационного файла. Для `/etc/sinver.toml` значение `database_path = "data/sinver.sqlite"` означает `/etc/data/sinver.sqlite`.
- Если конфигурация открыта через символическую ссылку, относительные пути отсчитываются от каталога её конечного файла.
- `~` раскрывается в домашний каталог пользователя, от имени которого работает SINVER. При запуске службы это пользователь `sinver`.

Для системной установки используйте абсолютные пути. Пользователь `sinver` должен читать конфигурацию, читать и изменять SQLite, а также создавать файлы в каталогах базы, резервных копий и журнала. Возможность записи в каталог базы нужна и для служебных файлов SQLite.

### Адрес и порт

| Значение `http_addr` | Результат |
|---|---|
| `127.0.0.1` | Доступ только с того же компьютера; подходит для локальной работы и NGINX на этом же сервере |
| Адрес конкретного интерфейса | Прослушивание выбранного интерфейса, если адрес назначен серверу |
| `0.0.0.0` | Прослушивание всех IPv4-интерфейсов |

**В SINVER нет встроенной аутентификации.** Привязка к внешнему интерфейсу сама по себе не ограничивает доступ. Для удалённого доступа оставьте `127.0.0.1` и настройте HTTPS и аутентификацию через NGINX по [быстрому старту](01_Quick_Start_RU.md).

Служба работает без прав root; используйте свободный непривилегированный порт, например `8080`. Порты ниже `1024` обычно требуют дополнительных прав. HTTPS завершается на NGINX; встроенный сервер SINVER принимает HTTP.

## Параметры запуска

| Аргумент | Действие |
|---|---|
| `--config ПУТЬ` | Выбрать конфигурационный файл; без аргумента читается `/etc/sinver.toml`. Относительный путь к самому конфигурационному файлу отсчитывается от текущего каталога запуска |
| `--debug` | Показывать текст необработанного исключения на странице ошибки. Интерактивный отладчик Flask не включается |
| `--init-if-missing` | Аргумент совместимости со старыми способами запуска. Отсутствующая база теперь создаётся автоматически, аргумент не меняет это поведение |
| `--help` | Вывести справку об аргументах и завершить программу |

Для запуска из каталога исходного кода выполните:

```bash
python3 sinver.py --config ./sinver.toml
```

Команда запускает приложение с конфигурацией из текущего каталога. Указанные в ней каталоги должны быть доступны текущему пользователю; пути системной установки обычно предназначены для пользователя `sinver`.

**Используйте `--debug` только в закрытом диагностическом окружении**: текст ошибки может раскрывать внутренние сведения о системе.

## Изменение настроек службы

После изменения `/etc/sinver.toml` перезапустите службу:

```bash
sudo systemctl restart sinver
```

Команда останавливает текущий процесс и запускает новый, который перечитывает конфигурацию. Если изменён только TOML, `daemon-reload` не требуется.

Проверьте состояние процесса:

```bash
systemctl is-active sinver
```

Ожидаемый результат:

```text
active
```

Активная служба может находиться в режиме обслуживания. Для проверки доступности основного интерфейса выполните на сервере SINVER:

```bash
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' http://127.0.0.1:8080/servers
```

Команда выводит только HTTP-код ответа; замените адрес и порт, если они изменены. Ожидаемый результат при готовой базе — `200`. Код `503` означает режим обслуживания; откройте страницу в браузере, чтобы прочитать причину.

После перезапуска **обновите открытые страницы перед отправкой форм**. Перезапуск сбрасывает сессии браузера и подготовленные планы синхронизации DNS; предварительный просмотр DNS потребуется выполнить заново.

### Права в стандартной установке

`make install` создаёт системного пользователя и группу `sinver`. Служба запускается от этой учётной записи с `UMask=0077`.

| Объект | Владелец | Права |
|---|---|---|
| `/etc/sinver.toml` | `root:sinver` | `0640`: root изменяет, группа sinver читает |
| `/var/lib/sinver`, `/var/log/sinver` | `sinver:sinver` | `0750`: запись владельцу, доступ к каталогу группе |
| `/var/lib/sinver/backups` | `sinver:sinver` | `0700`: доступ только владельцу |
| Файлы данных и журналов после установки | `sinver:sinver` | `0600`: чтение и запись только владельцу |

При переносе данных в другой каталог сохраните эти ограничения. **SQLite и резервные копии содержат пароль PostgreSQL из карточки зоны в открытом виде.** Служба использует `ProtectSystem=full`, поэтому размещайте изменяемые данные вне `/usr`, `/boot` и `/etc`.

## Проверка базы при запуске и режим обслуживания

Текущая версия приложения и схемы базы — `0.0.0`. При каждом запуске SINVER:

1. Создаёт отсутствующую SQLite-базу по поставляемой SQL-схеме.
2. Определяет версию базы и доступный путь обновления.
3. Проверяет целостность SQLite, внешние ключи, таблицы, столбцы, ограничения и индексы.
4. Открывает рабочий интерфейс, если база соответствует версии приложения.

При необходимости миграции или при ошибке проверки вместо всех вкладок появляется **Maintenance mode** — режим обслуживания. HTTP-сервер продолжает работать, но отвечает кодом `503`; работа с инвентаризацией заблокирована.

Если миграция возможна, страница показывает версии, план шагов и путь будущей резервной копии. Кнопка **«Подтвердить миграцию и создание резервной копии»** запускает обновление. Перед ним SINVER создаёт и проверяет копию SQLite. При успехе открывается интерфейс; при ошибке приложение пытается восстановить базу из этой копии и показывает результат.

Для старой базы без таблицы `sinver_meta` приложение предлагает добавить служебные таблицы. Это не исправляет произвольную устаревшую структуру инвентаризации: после добавления метаданных выполняется полная проверка.

Если база новее установленного приложения, установите совместимую версию SINVER или восстановите подходящую резервную копию. **Не изменяйте номер версии и структуру SQLite вручную для обхода проверки.** После устранения ошибки базы или прав доступа перезапустите службу: состояние проверки определяется при запуске.

## Журналы

В `log_file` записываются сообщения уровня `INFO` и выше: запуск, обслуживание базы, этапы синхронизации PowerDNS и HTTP-запросы встроенного сервера. Формат строки: время, уровень, источник и сообщение.

Для просмотра последних записей выполните:

```bash
sudo tail -n 30 /var/log/sinver/sinver.log
```

Команда показывает последние 30 строк файла. Среди сообщений успешного запуска ожидаются строки, содержащие:

```text
INFO sinver.maintenance: Post-migration validation: OK
INFO sinver.maintenance: database ready
INFO sinver: SINVER started successfully: http://127.0.0.1:8080
```

В реальном журнале перед ними указаны дата и время. При другом адресе или порте последняя строка отличается. Для ошибок, возникших до открытия файла журнала, смотрите журнал службы:

```bash
sudo journalctl -u sinver -n 30 --no-pager
```

Команда показывает последние 30 записей systemd. При успешном запуске ожидаются `Database version: 0.0.0; target: 0.0.0` и `database ready`; при проблеме обслуживания — `Maintenance error: ...` с причиной.

Автоматической ротации журнала нет. Настройте её средствами ОС и контролируйте свободное место; если файл журнала переименован, для открытия нового файла приложению нужен перезапуск.

## Резервные копии и восстановление

SINVER создаёт два вида копий в `database_backup_path`:

| Имя | Когда создаётся | Особенность |
|---|---|---|
| `sinver.sqlite.YYYYMMDD_HHMMSS_ffffff.bak` | Перед отдельным изменением SQLite через интерфейс; префикс соответствует имени файла базы | Копирование файла; время в локальном часовом поясе процесса. Одна операция интерфейса может создать несколько копий |
| `sinver-db-ВЕРСИЯ-YYYY-MM-DD_HH-MM-SS_ffffff.sqlite3` | Перед подтверждённой миграцией схемы | Копирование через API SQLite с проверкой целостности; время в UTC |

**Копии не удаляются автоматически.** Организуйте хранение вне сервера и срок удаления старых файлов. Страница обслуживания перечисляет только копии миграций `sinver-db-*.sqlite3`; копии `.bak` доступны в файловой системе.

Для надёжной дополнительной копии остановите службу, скопируйте файл базы и затем запустите службу. Копия SQLite не является резервной копией PostgreSQL PowerDNS: эти базы нужно сохранять отдельно.

### Ручное восстановление SQLite

Восстановление заменяет текущее содержимое инвентаризации. **Все изменения после выбранной копии будут потеряны.** Выберите копию, совместимую с установленной версией SINVER, и замените `ИМЯ_КОПИИ` в командах на её имя.

Для проверки копии нужна утилита командной строки SQLite. Установите её, если она отсутствует:

```bash
sudo apt install sqlite3
```

Команда устанавливает диагностический клиент, не изменяя базу SINVER.

1. Остановите приложение, чтобы оно не изменяло базу:

   ```bash
   sudo systemctl stop sinver
   ```

2. Проверьте выбранную копию в режиме только чтения:

   ```bash
   sudo -u sinver sqlite3 -readonly /var/lib/sinver/backups/ИМЯ_КОПИИ 'PRAGMA integrity_check; PRAGMA foreign_key_check;'
   ```

   Ожидаемый результат — одна строка `ok`. Проверка внешних ключей не выводит строк при отсутствии нарушений. При другом результате не используйте эту копию.

3. Сохраните нынешнюю базу перед заменой:

   ```bash
   sudo -u sinver cp --no-clobber /var/lib/sinver/sinver.sqlite /var/lib/sinver/backups/before-restore.sqlite
   ```

   Команда сохраняет возможность вернуться к текущему состоянию. Если `before-restore.sqlite` уже существует, выберите новое имя: `--no-clobber` не перезаписывает существующий файл.

4. Установите выбранную копию с правами пользователя службы:

   ```bash
   sudo install -o sinver -g sinver -m 0600 /var/lib/sinver/backups/ИМЯ_КОПИИ /var/lib/sinver/sinver.sqlite
   ```

   Команда заменяет рабочую базу и задаёт владельца и права доступа. Для нестандартных путей используйте значения из своего TOML.

5. Запустите приложение:

   ```bash
   sudo systemctl start sinver
   ```

   SINVER снова проверит базу. Откройте `/servers`: рабочий интерфейс означает готовность; страница обслуживания покажет необходимую миграцию или ошибку.

Восстановление SQLite не откатывает изменения, уже отправленные в PowerDNS. Перед следующей отправкой проверьте данные, номера `SERIAL` и предварительный просмотр во вкладке [DNS](10_DNS_RU.md).
