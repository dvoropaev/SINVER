# 2. Конфигурация

Для первого запуска подходит стандартная конфигурация. Меняйте параметры только при нестандартных сценариях: например, при переносе базы или выборе другого порта.

## 2.1. Файл настроек

Конфигурация SINVER выполняется с помощью файла `/etc/sinver.toml` в формате [TOML](https://toml.io/). Параметры записываются как `имя = значение`: строки — в кавычках, целые числа — без кавычек, комментарии начинаются с `#`. Все параметры находятся в корне файла, без секций.

Стандартная конфигурация:

```toml
database_path = "/var/lib/sinver/sinver.sqlite"
database_backup_path = "/var/lib/sinver/backups"
http_addr = "127.0.0.1"
http_port = 8080
log_file = "/var/log/sinver/sinver.log"
```

Настройки читаются при запуске. `make install` сохраняет существующий `/etc/sinver.toml`; изменение образца `sinver.toml` не меняет настройки установленной службы. Другой файл можно выбрать через `--config`.

## 2.2. Параметры

| Параметр | Тип и обязательность | Значение образца / значение по умолчанию | Назначение и требования |
|---|---|---|---|
| `database_path` | Непустая строка, **обязателен** | Образец: `/var/lib/sinver/sinver.sqlite`. Значения по умолчанию нет | Путь к SQLite-базе SINVER: серверы, IP-адреса, поддомены, справочники и зоны. Если файл отсутствует, SINVER создаёт базу. Процессу нужны чтение и запись файла, а также запись в каталог для служебных файлов SQLite |
| `database_backup_path` | Непустая строка, **обязателен** | Образец: `/var/lib/sinver/backups`. Значения по умолчанию нет | Каталог резервных копий SQLite. Должен быть доступен процессу на запись; укажите каталог, а не имя файла |
| `http_addr` | Непустая строка, необязателен | Образец и значение по умолчанию: `127.0.0.1` | Адрес встроенного HTTP-сервера. При `127.0.0.1` доступ возможен с того же компьютера и через NGINX на нём |
| `http_port` | Целое число, необязателен | Образец и значение по умолчанию: `8080` | TCP-порт HTTP: от `1` до `65535`. Строки, дробные числа и логические значения отклоняются. Для стандартной службы используйте свободный порт `1024` или выше |
| `log_file` | Непустая строка, **обязателен** | Образец: `/var/log/sinver/sinver.log`. Значения по умолчанию нет | Файл журнала в UTF-8. Родительский каталог создаётся при запуске, если права позволяют. Процессу нужны запись в файл и возможность создать его каталог |

> **Категорически не рекомендуется заменять `127.0.0.1` другим адресом: в SINVER пока не предусмотрена авторизация.** Для удалённого доступа сохраните этот адрес и настройте HTTPS и аутентификацию через NGINX по [быстрому старту](01_Quick_Start_RU.md).

Неизвестные ключи игнорируются; проверяйте написание параметров. Опечатка в обязательном параметре приводит к ошибке запуска.

Параметры подключения к PostgreSQL задаются для каждой зоны во вкладке [Zones](09_Zones_RU.md), а не в TOML. SQLite хранит данные SINVER, PostgreSQL — данные PowerDNS.

## 2.3. Разрешение путей

- Абсолютный путь используется как есть.
- Относительный путь отсчитывается от каталога выбранного конфигурационного файла. Для `/etc/sinver.toml` значение `database_path = "data/sinver.sqlite"` означает `/etc/data/sinver.sqlite`.
- Если конфигурационный файл открыт через символическую ссылку, отсчёт ведётся от каталога конечного файла.
- `~` раскрывается в домашний каталог пользователя процесса SINVER. При запуске службы это пользователь `sinver`. Переменные среды, например `$HOME`, не подставляются.

Для системной установки используйте абсолютные пути.

**Изменение `database_path` не переносит данные.** Если новый файл отсутствует, SINVER создаст пустую базу. Для переноса остановите службу, скопируйте действующую базу в новый путь, настройте владельца и права, затем измените конфигурацию и запустите службу.

## 2.4. Владельцы и доступ к файлам

`make install` создаёт системного пользователя и группу `sinver`. Служба работает от этой учётной записи с `UMask=0077`.

| Объект | Владелец | Права |
|---|---|---|
| `/etc/sinver.toml` | `root:sinver` | `0640`: root изменяет, группа sinver читает |
| `/var/lib/sinver`, `/var/log/sinver` | `sinver:sinver` | `0750`: запись владельцу, доступ к каталогу группе |
| `/var/lib/sinver/backups` и подкаталоги | `sinver:sinver` | `0700`: доступ только владельцу |
| Файлы данных, копий и журналов в стандартных каталогах после установки | `sinver:sinver` | `0600`: чтение и запись только владельцу |
| Программа, схема и миграции | `root:root` | Служба может читать, но не изменять |

При нестандартных путях создайте каталоги до запуска. Например:

```bash
sudo install -d -o sinver -g sinver -m 0750 /srv/sinver/data /srv/sinver/logs
sudo install -d -o sinver -g sinver -m 0700 /srv/sinver/backups
```

Пользователю `sinver` нужен доступ на проход через все родительские каталоги. Для существующей базы задайте владельца `sinver:sinver` и права `0600`.

Служба использует `ProtectSystem=full`, поэтому размещайте изменяемые данные вне `/usr`, `/boot` и `/etc`. Порты ниже `1024` обычно требуют дополнительных прав. При удалённом доступе HTTPS обслуживает NGINX, встроенный сервер SINVER принимает HTTP.

## 2.5. Изменение конфигурации и управление службой

Откройте конфигурацию и после изменения перезапустите службу:

```bash
sudoedit /etc/sinver.toml
sudo systemctl restart sinver
sudo systemctl status sinver --no-pager
```

Перезапуск запускает новый процесс, который перечитывает настройки. Если изменён только TOML, `daemon-reload` не требуется; эта команда нужна после изменения unit-файла или его переопределений.

| Действие | Команда |
|---|---|
| Запустить | `sudo systemctl start sinver` |
| Остановить | `sudo systemctl stop sinver` |
| Запускать при загрузке ОС | `sudo systemctl enable sinver` |
| Отключить автоматический запуск | `sudo systemctl disable sinver` |

Активная служба может находиться в режиме обслуживания. Проверьте доступность основного интерфейса на сервере SINVER:

```bash
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' http://127.0.0.1:8080/servers
```

Команда выводит HTTP-код ответа; при другом порте замените `8080`. Ожидаемый результат при готовой базе — `200`. Код `503` означает режим обслуживания; откройте страницу в браузере, чтобы прочитать причину.

**После перезапуска обновите открытые страницы перед отправкой форм.** Перезапуск сбрасывает сессии браузера и подготовленные планы синхронизации DNS. Отправка старой формы может дать HTTP `400`; предварительный просмотр DNS потребуется выполнить заново.

Если службе нужен другой конфигурационный файл, выполните `sudo systemctl edit sinver` и добавьте:

```ini
[Service]
ExecStart=
ExecStart=/usr/bin/sinver --config /srv/sinver/config/sinver.toml
```

Пустая строка `ExecStart=` сбрасывает прежнюю команду. Обеспечьте чтение нового файла пользователем `sinver`, затем выполните:

```bash
sudo systemctl daemon-reload
sudo systemctl restart sinver
```

## 2.6. Параметры командной строки

| Параметр | Действие |
|---|---|
| `--config ПУТЬ` | Выбрать TOML-файл. Без параметра используется `/etc/sinver.toml` |
| `--debug` | Показывать текст неожиданной ошибки на странице `Debug error`. Не включает интерактивный отладчик Flask и автоматический перезапуск кода |
| `--init-if-missing` | Флаг совместимости. Отсутствующая база создаётся автоматически и без этого флага |
| `-h`, `--help` | Показать справку и завершить работу |

Относительный путь к самому конфигурационному файлу отсчитывается от текущего каталога запуска.

Пример ручного запуска установленной программы:

```bash
sudo systemctl stop sinver
sudo -u sinver sh -c 'umask 0077; exec /usr/bin/sinver --config /etc/sinver.toml'
```

Процесс работает в переднем плане; для завершения нажмите `Ctrl+C`, затем запустите службу через `sudo systemctl start sinver`. Два экземпляра на одном порту запустить нельзя.

Используйте `--debug` только при диагностике с ограниченным доступом: текст ошибки может раскрывать внутренние сведения о системе.

## 2.7. Проверка базы и режим обслуживания

Текущая версия приложения и схемы базы — `0.0.0`. При каждом запуске SINVER:

1. Создаёт отсутствующую SQLite-базу по установленной SQL-схеме.
2. Определяет версию базы и доступный путь обновления.
3. Проверяет целостность SQLite, внешние ключи, таблицы, столбцы, ограничения и индексы.
4. Открывает рабочий интерфейс, если база соответствует версии приложения.

При необходимости миграции или ошибке проверки вместо вкладок появляется **Maintenance mode** — режим обслуживания. HTTP-сервер продолжает работать, но отвечает кодом `503`; изменение данных через обычный интерфейс недоступно.

Если миграция возможна, страница показывает версии, план шагов и путь будущей резервной копии. Кнопка **«Подтвердить миграцию и создание резервной копии»** запускает обновление. Перед ним SINVER создаёт и проверяет копию SQLite. При успехе открывается интерфейс; при ошибке приложение пытается восстановить базу из этой копии и показывает результат.

Для старой базы без таблицы `sinver_meta` SINVER предлагает добавить служебные таблицы. После их добавления выполняется полная проверка; произвольная устаревшая структура базы этим не исправляется.

Если база новее приложения, установите совместимую версию SINVER или восстановите подходящую копию. **Не меняйте номер версии и структуру SQLite вручную для обхода проверки.** После устранения ошибки базы или прав доступа перезапустите службу: проверка выполняется при запуске.

Ошибки чтения TOML и настройки файла журнала завершают запуск с кодом `1`. Причину ищите в журнале systemd.

## 2.8. Журналы

В `log_file` записываются сообщения уровня `INFO` и выше: запуск, обслуживание базы, этапы синхронизации PowerDNS и HTTP-запросы встроенного сервера. Формат строки: время, уровень, источник и сообщение.

Для просмотра последних записей выполните:

```bash
sudo tail -n 30 /var/log/sinver/sinver.log
```

Команда показывает последние 30 строк файла. При успешном запуске ожидаются сообщения:

```text
INFO sinver.maintenance: Post-migration validation: OK
INFO sinver.maintenance: database ready
INFO sinver: SINVER started successfully: http://127.0.0.1:8080
```

В журнале перед ними указаны дата и время; при другом порте последняя строка отличается. Ошибки, возникшие до открытия файла журнала, смотрите в журнале службы:

```bash
sudo journalctl -u sinver -n 30 --no-pager
```

Команда показывает последние 30 записей systemd. При проблеме обслуживания ищите `Maintenance error: ...` с причиной.

Автоматической ротации журнала нет. Настройте её средствами ОС и контролируйте свободное место. Если файл журнала переименован, для открытия нового файла нужен перезапуск SINVER.

## 2.9. Резервные копии и восстановление

SINVER создаёт два вида копий в `database_backup_path`:

| Имя | Когда создаётся | Особенность |
|---|---|---|
| `sinver.sqlite.YYYYMMDD_HHMMSS_ffffff.bak` | Перед отдельным изменением SQLite через интерфейс; префикс соответствует имени файла базы | Копирование файла; время в локальном часовом поясе процесса. Одна операция интерфейса может создать несколько копий |
| `sinver-db-ВЕРСИЯ-YYYY-MM-DD_HH-MM-SS_ffffff.sqlite3` | Перед подтверждённой миграцией схемы | Копирование через API SQLite с проверкой целостности; время в UTC |

**Копии не удаляются автоматически.** Организуйте хранение вне сервера и удаление старых файлов по своему сроку хранения. Страница обслуживания перечисляет только копии миграций `sinver-db-*.sqlite3`; копии `.bak` доступны в файловой системе.

Обычные копии создаются копированием файла. При параллельных изменениях или стороннем включении WAL такая копия может быть неполной; подробнее в [текущих проблемах](11_Current_Issues_RU.md). PostgreSQL PowerDNS сохраняйте отдельно.

Для согласованной дополнительной копии используйте команду `.backup` утилиты SQLite; её установка описана ниже. Остановите SINVER и другие процессы записи в эту базу, затем выполните:

```bash
sudo systemctl stop sinver
sudo -u sinver sh -c 'umask 0077; exec sqlite3 -readonly /var/lib/sinver/sinver.sqlite ".backup /var/lib/sinver/backups/manual.sqlite"'
sudo -u sinver sqlite3 -readonly /var/lib/sinver/backups/manual.sqlite 'PRAGMA integrity_check; PRAGMA foreign_key_check;'
sudo systemctl start sinver
```

Выберите новое имя вместо `manual.sqlite`, чтобы сохранить предыдущую копию. `.backup` использует API SQLite. Проверка должна вывести одну строку `ok` и не вывести нарушений внешних ключей. Если проверка не прошла, не используйте полученный файл для восстановления.

### Ручное восстановление SQLite

Восстановление заменяет текущие данные SINVER. **Все изменения после выбранной копии будут потеряны.** Выберите копию, совместимую с установленной версией SINVER, и замените `ИМЯ_КОПИИ` в командах на её имя.

Для проверки копии нужна утилита командной строки SQLite. Установите её, если она отсутствует:

```bash
sudo apt install sqlite3
```

Команда устанавливает средство просмотра базы данных, не изменяя базу SINVER.

1. Остановите приложение, чтобы оно не изменяло базу:

   ```bash
   sudo systemctl stop sinver
   ```

   Другие процессы записи в эту SQLite-базу также должны быть остановлены.

2. Проверьте выбранную копию в режиме только чтения:

   ```bash
   sudo -u sinver sqlite3 -readonly /var/lib/sinver/backups/ИМЯ_КОПИИ 'PRAGMA integrity_check; PRAGMA foreign_key_check;'
   ```

   Ожидаемый результат — одна строка `ok`. Проверка внешних ключей не выводит строк при отсутствии нарушений. При другом результате не используйте эту копию. Флаг `-readonly` также исключает создание пустого файла при опечатке в пути.

3. Сохраните нынешнюю базу перед заменой:

   ```bash
   sudo -u sinver cp --no-clobber /var/lib/sinver/sinver.sqlite /var/lib/sinver/backups/before-restore.sqlite
   ```

   Команда сохраняет возможность вернуться к текущему состоянию. Если `before-restore.sqlite` уже существует, выберите новое имя: `--no-clobber` не перезаписывает существующий файл.

4. Установите выбранную копию с правами пользователя службы:

   ```bash
   sudo install -o sinver -g sinver -m 0600 /var/lib/sinver/backups/ИМЯ_КОПИИ /var/lib/sinver/sinver.sqlite
   ```

   Команда заменяет рабочую базу и задаёт владельца и права. Для нестандартных путей используйте значения из своего TOML.

5. Запустите приложение:

   ```bash
   sudo systemctl start sinver
   sudo systemctl status sinver --no-pager
   ```

   SINVER снова проверит базу. Откройте `/servers`: рабочий интерфейс означает готовность; страница обслуживания покажет необходимую миграцию или ошибку.

Этот порядок рассчитан на стандартный режим SQLite приложения. Если остались файлы `-wal`, `-shm` или незавершённый journal от других процессов, сначала завершите или восстановите их средствами SQLite. Не удаляйте служебные файлы для обхода ошибки.

Восстановление SQLite не откатывает изменения, уже отправленные в PowerDNS. Перед следующей отправкой проверьте данные, номера `SERIAL` и предварительный план синхронизации.
