# 6. Поддомены — Subdomains

[Содержание](README_RU.md) · [Назад: IP-адреса](05_IP_Addresses_RU.MD) · [Далее: Роли](07_Roles_RU.MD)

Вкладка **Subdomains** (`/subdomains`) задаёт DNS-имена, связанные с IP-адресами из инвентаря. Один поддомен может использовать несколько адресов, в том числе адреса разных серверов. Один IP может использоваться несколькими поддоменами.

В текущей версии доступны **только A и AAAA**: A связывает имя с IPv4, AAAA — с IPv6. Для одного имени с обеими версиями IP создайте две отдельные карточки. Параметры SOA задаются в [Zones](09_Zones_RU.MD); CNAME, TXT, MX, NS, SRV и CAA через эту вкладку не настраиваются.

## 6.1. Поля поддомена

| Поле интерфейса | Обязательность | Смысл и допустимые значения |
| --- | --- | --- |
| **Type** | Обязательно | `A` или `AAAA`. SINVER проверяет тип при создании и сохранении. |
| **Name** | Обязательно для корректной карточки; форма создания требует заполнения | Имя относительно выбранной зоны: `www`, `api`, `api.internal`; `@` означает саму зону. Максимум 255 символов. Начальные и конечные пробелы удаляются. Синтаксис DNS-имени SINVER не проверяет. |
| **Zone** | Обязательно | Одна существующая зона. Для `Name = api` и `Zone = example.net` итоговое имя — `api.example.net`. |
| **Role** | Необязательно | Собственная роль поддомена из [Roles](07_Roles_RU.MD) либо `None`. |
| **Linked IP addresses** | Необязательно для сохранения; необходимо для формирования A/AAAA | Один или несколько IP-адресов из инвентаря. Поле появляется только в карточке после создания. Можно оставить выбор пустым, но DNS-записи тогда не будет. |

Сочетание **Type + Name + Zone** должно быть уникальным. Например, `A www example.net` можно создать один раз, а `AAAA www example.net` — отдельно. Добавляйте несколько IPv4 к одной карточке A, а не создавайте несколько одинаковых карточек.

**В Name вводите относительное имя, а не полный домен.** `www.example.net` при зоне `example.net` превратится в `www.example.net.example.net`. Завершающую точку добавлять не нужно. Для предсказуемой уникальности используйте нижний регистр.

Для обычных DNS-имён используйте латинские буквы, цифры и дефисы; дефис не должен стоять в начале или конце части имени. Каждая часть между точками должна иметь длину не более 63 символов, а полное имя вместе с зоной — не более 253 символов без завершающей точки. Эти ограничения DNS приложение автоматически не проверяет.

## 6.2. Список и отбор

| Столбец | Что показывает |
| --- | --- |
| **Color** | Цвет собственной роли. При её отсутствии — цвет одного связанного IP с учётом роли его сервера; правила приведены в [главе Roles](07_Roles_RU.MD). |
| **Type** | Тип записи. |
| **Subdomain** | Относительное имя или `@`. Ссылка открывает карточку. |
| **Zone** | Зона, к которой относится имя. |
| **IP addresses** | Все связанные IP-адреса, в том числе адреса неподходящей версии. |
| **Role** | Только собственная роль поддомена либо `—`. |

Доступны фильтры **Type** (`Any`, `A`, `AAAA`), **Zone** (`Any` или зона) и **Role** (`Any` или собственная роль поддомена). Заполненные фильтры объединяются условием «и». **Apply** применяет отбор, **Reset** сбрасывает его.

**Sort by** задаёт сортировку по возрастанию: `name` — относительное имя, `type` — тип записи, `zone` — зона, `role` — собственная роль. По умолчанию используется `name`. Текстового поиска по имени нет. Особенность отображения сортировки описана в [текущих проблемах](11_Current_Issues_RU.MD).

## 6.3. Создание и привязка IP

1. Убедитесь, что зона и нужные [IP-адреса](05_IP_Addresses_RU.MD) уже созданы.
2. Заполните **Add subdomain** и нажмите **Create**. Поддомен создаётся без IP-связей.
3. Откройте карточку по ссылке в **Subdomain** и нажмите **Edit**.
4. В **Linked IP addresses** выберите подходящие адреса. Для нескольких отдельных строк используйте `Ctrl` в Windows/Linux или `Command` в macOS; для диапазона — `Shift`.
5. Нажмите **Save**. Общие правила редактирования описаны в [главе о веб-интерфейсе](03_Web_Interface_RU.MD).

Сохранение заменяет набор связей текущим выбором: ранее выбранные, но теперь снятые адреса отвязываются. Сами IP-адреса не удаляются.

**Для A выбирайте IPv4, для AAAA — IPv6.** Интерфейс позволяет выбрать адрес любой версии, но при формировании DNS несовместимые адреса молча пропускаются. Наличие IP в таблице само по себе не доказывает наличие записи в DNS; проверьте результат на вкладке [DNS](10_DNS_RU.MD).

Блок **Servers mapped by this subdomain** показывает серверы выбранных IP. Имена в этом блоке не являются ссылками. Зона сервера может отличаться от зоны поддомена: привязка использует сам IP, а не основное имя сервера.

При изменении типа записи проверьте и замените выбранные IP. При изменении зоны или имени связи сохраняются, но итоговое DNS-имя меняется.

## 6.4. Примеры

### Одно имя с IPv4 и IPv6

Чтобы `www.example.net` указывало на оба адреса сервера `web01`, создайте:

| Type | Name | Zone | Linked IP addresses | Результат |
| --- | --- | --- | --- | --- |
| A | `www` | `example.net` | `192.0.2.10` | `www.example.net A 192.0.2.10` |
| AAAA | `www` | `example.net` | `2001:db8::10` | `www.example.net AAAA 2001:db8::10` |

### Адреса нескольких серверов

Для `api.example.net` создайте одну карточку **A / api / example.net** и выберите IPv4 `192.0.2.10` и `192.0.2.20`. Получатся две A-записи одного имени.

Это публикует несколько адресов; SINVER не проверяет состояние серверов и не исключает недоступный адрес. Если нужен единый цвет для карточки, назначьте ей собственную роль, например `API`.

### Запись самой зоны

Создайте **A / @ / example.net**, затем выберите `192.0.2.10`. Итог — `example.net A 192.0.2.10`. В списке `@` остаётся относительным обозначением. Некоторые блоки связанных объектов отображают его как `@.example.net`; это особенность отображения, описанная в [текущих проблемах](11_Current_Issues_RU.MD).

После настройки любого примера отдельно выполните синхронизацию с PowerDNS либо экспорт зоны на вкладке **DNS**.

## 6.5. Удаление

Нажмите **Delete subdomain** в карточке и подтвердите действие. Удаляется поддомен и его связи с IP; адреса, серверы и зона сохраняются.

Чтобы убрать один адрес из DNS-имени, достаточно снять его выбор в **Linked IP addresses** и сохранить карточку. Удалять весь поддомен не требуется. Изменение опубликованной зоны выполняется отдельно через **DNS**.
