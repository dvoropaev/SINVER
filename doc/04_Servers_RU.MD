# 4. Серверы — Servers

[Содержание](README_RU.md) · [Назад: Веб-интерфейс](03_Web_Interface_RU.MD) · [Далее: IP-адреса](05_IP_Addresses_RU.MD)

Вкладка **Servers** (`/servers`) содержит инвентарные карточки серверов: имя, назначение, размещение и связанные IP-адреса. SINVER хранит введённые сведения; он не подключается к серверам и не проверяет их доступность.

Карточка сервера и DNS-запись — разные сущности. Для автоматического формирования записи имени сервера нужны **Primary zone** и основной IP-адрес. Дополнительные имена задаются отдельно во вкладке [Subdomains](06_Subdomains_RU.MD).

## 4.1. Поля сервера

Поля формы **Add server** и карточки сервера совпадают.

| Поле интерфейса | Обязательность | Смысл и допустимые значения |
| --- | --- | --- |
| **Hostname** | Обязательно для корректной карточки; форма создания требует заполнения | Короткое имя, например `web01`. В базе оно уникально среди всех серверов, независимо от зоны; максимум 255 символов. Начальные и конечные пробелы удаляются при сохранении. Для DNS используйте короткое имя длиной до 63 символов, без зоны и завершающей точки, в нижнем регистре, с латинскими буквами, цифрами и дефисами; дефис не должен стоять в начале или конце. SINVER не проверяет синтаксис DNS-имени. |
| **Primary zone** | Необязательно | Одна из созданных [зон](09_Zones_RU.MD) либо `None`. При выборе `example.net` имя `web01` отображается как `web01.example.net`. В эту зону попадает автоматическая A-запись основного IPv4-адреса или AAAA-запись основного IPv6-адреса. |
| **Role** | Необязательно | Назначение сервера из справочника [Roles](07_Roles_RU.MD), например `Web`, либо `None`. Определяет цветовую метку сервера. |
| **Hosting** | Необязательно | Место размещения из справочника [Hostings](08_Hostings_RU.MD), например `Example VPS`, либо `None`. |
| **Description** | Необязательно | Свободный текст: назначение, владелец, особенности обслуживания. Ограничение длины в схеме базы не задано. |

**Не вводите полный домен в Hostname при выбранной зоне.** Например, `web01.example.net` вместе с зоной `example.net` даст имя `web01.example.net.example.net`.

Для обычного короткого DNS-имени используйте от 1 до 63 символов; дефис допустим внутри имени, но не в начале или конце. Полное имя вместе с зоной должно укладываться в 253 символа без завершающей точки. Эти правила SINVER автоматически не проверяет.

Роли, хостинги и зоны создайте заранее, если хотите назначить их при добавлении сервера. Сервер без них можно создать сразу и дополнить позже.

## 4.2. Список и отбор серверов

| Столбец | Что показывает |
| --- | --- |
| **Color** | Цвет роли сервера; при отсутствии роли метки нет. |
| **Hostname** | Короткое имя либо имя с основной зоной. Ссылка открывает карточку. |
| **Description** | Описание сервера полностью. |
| **Primary IP** | Единственный основной адрес; `—`, если он не назначен. |
| **IP addresses** | Все IP-адреса сервера, включая основной. |
| **Role** | Назначенная роль либо `—`. |
| **Hosting** | Назначенный хостинг либо `—`. |
| **Paid until** | Дата оплаты из карточки хостинга. Отдельной даты оплаты сервера нет. |

Для отбора доступны **Role** и **Hosting**. `Any` означает отсутствие ограничения; при заполнении обоих полей сервер должен соответствовать обоим условиям. **Apply** применяет отбор, **Reset** возвращает полный список.

**Sort by** сортирует по возрастанию: `hostname` — по короткому имени, `role` — по имени роли, `paid until` — по дате хостинга. По умолчанию используется `hostname`. Текстового поиска по имени или описанию на этой вкладке нет. Особенность отображения выбранной сортировки описана в [текущих проблемах](11_Current_Issues_RU.MD).

## 4.3. Создание, просмотр и изменение

1. Откройте **Servers** и заполните **Add server**.
2. Нажмите **Create**. Новый сервер появится в таблице, пока без IP-адресов.
3. Откройте его по ссылке в **Hostname**. Для изменения используйте **Edit**, затем **Save**; общая механика описана в [главе о веб-интерфейсе](03_Web_Interface_RU.MD).
4. Добавьте адреса на вкладке [IP addresses](05_IP_Addresses_RU.MD), выбрав этот сервер.

В карточке доступны связанные объекты:

| Блок | Содержимое и переходы |
| --- | --- |
| **IP addresses** | Адреса сервера со ссылками на их карточки. Основной помечен `(Primary)`. |
| **Subdomains linked to this server** | Поддомены, связанные хотя бы с одним IP этого сервера. Ссылка открывает карточку поддомена. |

Изменение **Hostname** или **Primary zone** меняет автоматически формируемое DNS-имя сервера. Поддомены при этом сохраняют собственные имена и зоны. Изменение роли или хостинга не меняет IP-адреса.

## 4.4. Пример: сервер веб-приложения

Создайте карточку со значениями:

| Поле | Значение |
| --- | --- |
| Hostname | `web01` |
| Primary zone | `example.net` |
| Role | `Web` |
| Hosting | `Example VPS` |
| Description | `Веб-приложение; ответственный — команда разработки` |

Затем добавьте IPv4 `192.0.2.10` и назначьте его основным. При формировании DNS для `example.net` появится `web01.example.net A 192.0.2.10`. Сохранение карточки само по себе не отправляет запись в PowerDNS: выполните действия из [главы DNS](10_DNS_RU.MD).

## 4.5. Удаление

Кнопка **Delete server** находится в карточке и требует подтверждения браузера.

**Удаляются сервер, все принадлежащие ему IP-адреса и связи этих адресов с поддоменами.** Сами поддомены, роли, хостинг и зона остаются. Поддомен, потерявший все подходящие адреса, перестаёт формировать A/AAAA-записи.

Перед удалением проверьте оба блока связанных объектов. Чтобы сохранить IP-адреса, сначала переназначьте их другому серверу в карточках адресов. Для изменения опубликованных записей после удаления отдельно выполните синхронизацию DNS.
