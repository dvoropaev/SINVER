# 4. Серверы — Servers

[← Назад](03_Web_Interface_RU.md) · [Содержание](README_RU.md#содержание) · [Вперёд →](05_IP_Addresses_RU.md)

Вкладка **Servers** хранит перечень серверов: их имена, назначение, размещение и связанные IP-адреса. Запись сервера — это учётная карточка. Для её создания подключаться к самому серверу не требуется.

Правила работы с формами, кнопками **Create**, **Edit**, **Save**, **Apply** и **Reset** описаны в [главе о веб-интерфейсе](03_Web_Interface_RU.md).

## Список серверов

| Столбец | Что показывает |
| --- | --- |
| **Color** | Цвет роли, назначенной серверу. Если роль не назначена, индикатор отсутствует. |
| **Hostname** | Имя сервера. При выбранной основной зоне отображается полное имя, например `app-01.infra.example.net`; иначе — только `app-01`. Ссылка открывает карточку. |
| **Description** | Описание сервера. Во всплывающей подсказке строки отображаются первые 50 символов описания. |
| **Primary IP** | Единственный адрес, отмеченный как основной. Если основной адрес не выбран, отображается `—`. |
| **IP addresses** | Все IP-адреса сервера, включая основной, по одному в строке. |
| **Role** | Роль сервера, например `application`. Подробнее — в [главе Roles](07_Roles_RU.md). |
| **Hosting** | Провайдер или место размещения, выбранное из справочника [Hostings](08_Hostings_RU.md). |
| **Paid until** | Дата окончания оплаты выбранного хостинга. Изменяется в карточке хостинга, одна и та же для всех связанных с ним серверов. |

### Фильтры и сортировка

| Поле | Значения и действие |
| --- | --- |
| **Role** | `Any` — все роли; название роли — только серверы с этой ролью. |
| **Hosting** | `Any` — все хостинги; название хостинга — только серверы, размещённые у него. |
| **Sort by** | `hostname` — по имени без добавленной зоны; `role` — по названию роли; `paid until` — по дате оплаты хостинга. |

Несколько фильтров применяются одновременно. Например, выберите роль `application` и определённый хостинг, чтобы увидеть серверы приложений у этого провайдера. Сортировка выполняется по возрастанию, для текста — без учёта регистра. По умолчанию используется `hostname`.

## Создание и поля карточки

Внизу списка находится форма **Add server**. Она содержит те же редактируемые поля, что и карточка сервера.

| Поле | Назначение, значения и ограничения | Пример |
| --- | --- | --- |
| **Hostname** | Обязательное имя сервера, до 255 символов. Уникально во всей базе SINVER, независимо от основной зоны. При использовании DNS вводите относительное имя: зона будет добавлена автоматически. | `app-01` |
| **Primary zone** | Основная DNS-зона из вкладки **Zones**. `None` — зона не выбрана. Определяет полное имя сервера и зону его автоматической записи DNS. | `infra.example.net` |
| **Role** | Необязательная роль из вкладки **Roles**. `None` — роль не назначена. Роль описывает назначение сервера и задаёт цвет его индикатора. | `application` |
| **Hosting** | Необязательный хостинг из вкладки **Hostings**. `None` — место размещения не указано. | Название вашего провайдера |
| **Description** | Необязательный текст произвольной длины. Укажите сведения, необходимые для обслуживания: назначение, площадку, ответственного или особенности конфигурации. | `Сервер приложения; площадка А; ответственный — команда эксплуатации` |

> **Важно:** если основная зона — `infra.example.net`, вводите **Hostname** как `app-01`, а не `app-01.infra.example.net`. SINVER добавляет зону к введённой строке и не проверяет корректность итогового имени. Для обычного имени используйте латинские буквы, цифры и дефис; дефис не должен находиться в начале или конце метки, длина отдельной метки — не более 63 символов. Не добавляйте завершающую точку.

Перед заполнением формы создайте нужные элементы справочников. Основная зона, роль и хостинг могут оставаться `None`; их можно назначить позднее.

### Пример: учёт сервера приложения

1. Создайте зону `infra.example.net` во вкладке [Zones](09_Zones_RU.md).
2. В **Add server** укажите **Hostname** = `app-01` и **Primary zone** = `infra.example.net`.
3. При необходимости выберите роль и хостинг, заполните описание. Нажмите **Create**.
4. В списке появится `app-01.infra.example.net`. Откройте карточку по ссылке в **Hostname**.
5. Добавьте адрес `192.0.2.10` во вкладке [IP addresses](05_IP_Addresses_RU.md), выбрав сервер `app-01` и **Primary** = `Yes`.

В карточке появится адрес с отметкой **(Primary)**. При построении записей зоны SINVER создаст:

```text
app-01.infra.example.net. IN A 192.0.2.10
```

Эта строка означает: имя `app-01.infra.example.net` связано с IPv4-адресом `192.0.2.10`. Если основной адрес относится к IPv6, создаётся запись `AAAA`. У сервера может быть **не более одного основного адреса суммарно для IPv4 и IPv6**. Порядок передачи записей в PowerDNS описан в [главе DNS](10_DNS_RU.md).

При **Primary zone** = `None` или отсутствии основного IP автоматическая запись имени сервера не формируется. Адреса такого сервера всё равно можно связать с [поддоменами](06_Subdomains_RU.md).

## Связанные сведения в карточке

| Блок | Содержание и использование |
| --- | --- |
| **IP addresses** | Адреса, назначенные серверу. Ссылка на адрес открывает его карточку; **(Primary)** отмечает основной. Добавление и перенос адресов выполняются во вкладке **IP addresses**. |
| **Subdomains linked to this server** | Поддомены, связанные хотя бы с одним адресом сервера. Каждая ссылка содержит тип записи, имя и зону. Связи задаются в карточках **Subdomains**. |

При смене **Primary zone** полное имя сервера и его автоматическая запись переходят в новую зону. Уже существующие поддомены сохраняют свои зоны и связи с IP-адресами.

## Удаление сервера

**Delete server** в карточке запрашивает подтверждение и удаляет сервер. Вместе с ним удаляются все назначенные ему IP-адреса и их связи с поддоменами. Сами поддомены, роли, хостинги и зоны сохраняются.

Перед удалением проверьте **Subdomains linked to this server**: поддомен может остаться без адресов. Удалённые адреса перестанут участвовать в следующем построении записей DNS; для изменения записей в PowerDNS требуется выполнить синхронизацию.

Ошибки проверки имён и отображения выбранной сортировки перечислены в [текущих проблемах](11_Current_Issues_RU.md).
