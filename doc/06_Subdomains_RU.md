# 6. Поддомены — Subdomains

[← Назад](05_IP_Addresses_RU.md) · [Содержание](README_RU.md#содержание) · [Вперёд →](07_Roles_RU.md)

Вкладка **Subdomains** задаёт дополнительные DNS-имена и связывает их с IP-адресами из инвентаря. Имя может указывать на один или несколько адресов, в том числе адреса разных серверов. Поддерживаются **только записи `A` для IPv4 и `AAAA` для IPv6**. Параметры `SOA` задаются во вкладке [Zones](09_Zones_RU.md).

Правила работы с формами и кнопками описаны в [главе о веб-интерфейсе](03_Web_Interface_RU.md).

## Список поддоменов

| Столбец | Что показывает |
| --- | --- |
| **Color** | Цвет собственной роли поддомена. При её отсутствии цвет определяется связанным IP: сначала выбирается основной адрес, затем адрес с наименьшим внутренним ID. Используется роль этого IP либо роль его сервера. Если у выбранного IP и его сервера нет роли, индикатор отсутствует. |
| **Type** | Тип записи: `A` или `AAAA`. |
| **Subdomain** | Относительное имя, например `app`, или `@` для самой зоны. Ссылка открывает карточку. |
| **Zone** | DNS-зона, к которой относится имя, например `infra.example.net`. |
| **IP addresses** | Все связанные IP-адреса, по одному в строке. `—` означает, что адреса не выбраны. |
| **Role** | Роль, назначенная непосредственно поддомену. При её отсутствии отображается `—`, даже если цвет получен от связанного IP или сервера. |

### Фильтры и сортировка

| Поле | Значения и действие |
| --- | --- |
| **Type** | `Any` — все типы; `A` или `AAAA` — только выбранный тип записи. |
| **Zone** | `Any` — все зоны; название зоны — только её поддомены. |
| **Role** | `Any` — все роли; название роли — поддомены с этой собственной ролью. Роли IP и серверов при фильтрации не учитываются. |
| **Sort by** | `name` — по относительному имени; `type` — по типу записи; `zone` — по названию зоны; `role` — по собственной роли. |

Фильтры применяются одновременно. Например, **Zone** = `infra.example.net` и **Type** = `AAAA` покажут IPv6-записи выбранной зоны. Сортировка выполняется по возрастанию, без учёта регистра; по умолчанию — `name`.

## Создание и поля карточки

Перед созданием поддомена добавьте [зону](09_Zones_RU.md). Для последующей привязки адресов создайте сервер и его [IP-адреса](05_IP_Addresses_RU.md).

| Поле | Назначение, значения и ограничения | Пример |
| --- | --- | --- |
| **Type** | Обязательный тип: `A` или `AAAA`; по умолчанию `A`. | `A` |
| **Name** | Обязательное относительное имя, до 255 символов, или `@` для самой зоны. Зона добавляется автоматически. Сочетание **Type + Name + Zone** должно быть уникальным. | `app` |
| **Zone** | Обязательная существующая зона. Она определяет полное DNS-имя записи. | `infra.example.net` |
| **Role** | Необязательная роль из [Roles](07_Roles_RU.md). `None` — собственная роль отсутствует. Используется для обозначения назначения поддомена и цветового индикатора. | `application` |
| **Linked IP addresses** | Только в карточке: список адресов из всего инвентаря с возможностью выбора нескольких. Для `A` выбирайте IPv4, для `AAAA` — IPv6. | `192.0.2.10` для `A` |

При **Name** = `app` и **Zone** = `infra.example.net` полное имя будет `app.infra.example.net`. Относительное имя может содержать несколько меток: `api.app` даст `api.app.infra.example.net`. Значение `@` даст имя самой зоны — `infra.example.net`.

> **Важно:** не вводите в **Name** полное имя вместе с зоной и не добавляйте завершающую точку. SINVER не проверяет DNS-синтаксис имени. Для обычных меток используйте латинские буквы, цифры и дефис, до 63 символов в каждой метке, без дефиса в начале и конце.

Для одного имени допустимы две отдельные карточки: `A app` и `AAAA app` в одной зоне. Вторую карточку с теми же типом, именем и зоной создать нельзя. Чтобы добавить ещё один адрес тому же имени и типу, расширьте **Linked IP addresses** существующей карточки.

### Привязка IP-адресов

Форма **Add subdomain** создаёт карточку без связанных адресов. После **Create** откройте её по ссылке **Subdomain**, нажмите **Edit**, выберите адреса в **Linked IP addresses** и сохраните.

Чтобы выделить несколько отдельных строк, удерживайте `Ctrl` при щелчке; на macOS — `Cmd`. Для последовательного диапазона используйте `Shift`. Повторный щелчок с `Ctrl` или `Cmd` снимает выделение. После сохранения поддомен связан только с выделенными адресами; сохранение без выделения удалит все его связи.

Список содержит адреса всех серверов и обоих семейств. При формировании DNS учитываются только IPv4 для `A` и IPv6 для `AAAA`. Связанный адрес неподходящего семейства виден в интерфейсе, но запись DNS для него не создаётся.

## Примеры использования

### Дополнительное имя сервиса

Пусть сервер `app-01` имеет адрес `192.0.2.10` и основную зону `infra.example.net`. Чтобы обращаться к сервису по имени `app.infra.example.net`:

1. В **Add subdomain** выберите **Type** = `A`, **Name** = `app`, **Zone** = `infra.example.net`.
2. Нажмите **Create**, откройте созданную карточку и включите редактирование.
3. В **Linked IP addresses** выделите `192.0.2.10`, затем сохраните.

При построении DNS будет добавлена запись:

```text
app.infra.example.net. IN A 192.0.2.10
```

Она связывает дополнительное имя сервиса с IPv4-адресом сервера. Имя сервера `app-01.infra.example.net` и имя сервиса `app.infra.example.net` существуют независимо.

### Одно имя с IPv4 и IPv6

Добавьте серверу `app-01` адрес `2001:db8::10`. Затем создайте вторую карточку с **Type** = `AAAA`, **Name** = `app` и той же зоной; свяжите её с IPv6-адресом.

Результат построения:

```text
app.infra.example.net. IN A 192.0.2.10
app.infra.example.net. IN AAAA 2001:db8::10
```

DNS-клиент сможет получить оба семейства адресов. Отметка **Primary** у связанных адресов для этого сценария не требуется.

### Несколько серверов за одним именем

Создайте второй сервер `app-02` с IPv4-адресом `192.0.2.11`. В карточке `A app` выделите одновременно `192.0.2.10` и `192.0.2.11`.

Для `app.infra.example.net` будут сформированы две записи `A`, по одной на каждый адрес. Этот сценарий подходит для сервисов, доступных на нескольких узлах. SINVER не проверяет доступность узлов и не удаляет из DNS адреса недоступных серверов; DNS также не гарантирует равномерное распределение запросов между ними.

### Имя самой зоны

Чтобы связать `infra.example.net` с адресом `192.0.2.10`, создайте поддомен **Type** = `A`, **Name** = `@`, **Zone** = `infra.example.net` и назначьте IPv4-адрес. При построении записи символ `@` заменяется именем зоны:

```text
infra.example.net. IN A 192.0.2.10
```

Проверка результата и передача записей в PowerDNS выполняются во вкладке [DNS](10_DNS_RU.md).

## Карточка и удаление

Заголовок **Subdomain #N** содержит внутренний номер карточки. В карточке можно изменить тип, имя, зону, роль и набор связанных адресов. После смены типа проверьте семейство выделенных адресов.

Блок **Servers mapped by this subdomain** показывает серверы, которым принадлежат выбранные IP-адреса. Эта связь определяется через адреса, отдельного поля выбора сервера у поддомена нет. Зона поддомена может отличаться от **Primary zone** этих серверов.

**Delete subdomain** запрашивает подтверждение и удаляет карточку вместе с её связями. IP-адреса и серверы сохраняются. Если для одного имени есть карточки `A` и `AAAA`, удаление одной сохраняет вторую.

Ограничения поддерживаемых типов, проверки имён и отображения адресов перечислены в [главе о текущих проблемах](11_Current_Issues_RU.md).
