# 9. Zones — DNS-зоны

[Содержание](README_RU.md) · [Назад: Хостинги](08_Hostings_RU.MD) · [Далее: DNS](10_DNS_RU.MD)

Вкладка **Zones** хранит параметры DNS-зон, их SOA-записей и подключения к PostgreSQL, который использует PowerDNS. Зона — область DNS с общими правилами обслуживания, например `example.net`. Она связывает основное имя сервера и поддомены с доменным именем.

**Создание или изменение зоны в SINVER не изменяет DNS-сервер.** Публикация выполняется отдельно на вкладке [DNS](10_DNS_RU.MD). Создать саму зону в PowerDNS также нужно заранее.

Общие действия с формами описаны в главе [веб-интерфейс](03_Web_Interface_RU.MD).

## 9.1. Список и поиск

Таблица содержит имя зоны, все семь параметров SOA, адрес PostgreSQL, пользователя PostgreSQL и описание. Нажмите имя зоны, чтобы открыть её карточку. В списке описание сокращается до первых 50 символов; полное описание доступно в карточке. Имя БД и пароль PostgreSQL в таблице не показаны.

Каждое поле фильтра с окончанием **contains** ищет часть значения:

| Фильтр | Где выполняется поиск |
| --- | --- |
| `Zone contains` | Имя зоны |
| `MNAME contains` | Имя основного DNS-сервера |
| `RNAME contains` | Контакт администратора в формате SOA |
| `SERIAL contains` | Серийный номер зоны |
| `REFRESH contains` | Интервал проверки обновлений |
| `RETRY contains` | Интервал повторного обращения |
| `EXPIRE contains` | Срок действия данных вторичного сервера |
| `MINIMUM contains` | Параметр отрицательного кеширования |
| `psql address contains` | Адрес PostgreSQL |
| `psql user contains` | Пользователь PostgreSQL |
| `Description contains` | Полное описание зоны |

Непустые фильтры действуют одновременно. Например, `Zone contains = example` и `psql user contains = sinver` найдут зоны с обоими совпадениями. Числовые параметры тоже фильтруются как текст: `REFRESH contains = 60` найдёт `60`, `600` и `3600`. Символы `%` и `_` имеют значение шаблонов SQL LIKE: любое число символов и один символ соответственно.

**Sort by** сортирует по одному из тех же 11 полей по возрастанию. Параметры SOA хранятся как текст, поэтому их сортировка не является числовой. По умолчанию зоны отсортированы по имени. Нажмите **Apply**, чтобы применить фильтры, или **Reset**, чтобы вернуть полный список.

## 9.2. Поля зоны

В форме **Add zone** заполните поля и нажмите **Create**. Для корректной зоны обязательны `Zone` и все параметры SOA; поля подключения и описание можно оставить пустыми.

| Поле создания / поле карточки | Значение и допустимое заполнение | Пример |
| --- | --- | --- |
| `Zone` / `zone` | Уникальное доменное имя зоны, до 255 символов. Указывайте без схемы, пути и завершающей точки; оно должно точно совпадать с `domains.name` в PowerDNS | `example.net` |
| `MNAME` / `mname` | Полное доменное имя основного DNS-сервера для SOA | `ns1.example.net.` |
| `RNAME` / `rname` | Контакт администратора в формате DNS-имени; знак `@` в адресе электронной почты заменён точкой | `hostmaster.example.net.` для `hostmaster@example.net` |
| `SERIAL` / `serial` | Текущий серийный номер SOA: целое десятичное число от `0` до `4294967295`. При первой настройке PowerDNS скопируйте его из существующей удалённой SOA | `2610071200` |
| `REFRESH` / `refresh` | Через сколько секунд вторичный DNS-сервер проверяет обновление зоны | `3600` — 1 час |
| `RETRY` / `retry` | Через сколько секунд вторичный сервер повторяет неудачную проверку | `600` — 10 минут |
| `EXPIRE` / `expire` | Через сколько секунд без успешного обновления вторичный сервер перестаёт обслуживать зону | `1209600` — 14 суток |
| `MINIMUM` / `minimum` | Параметр срока отрицательного кеширования: хранения ответа об отсутствии имени или записи | `300` — 5 минут |
| `PostgreSQL address` / `psql_address` | Имя хоста, IPv4/IPv6-адрес или абсолютный путь к каталогу Unix-сокета PostgreSQL. До 256 символов | `127.0.0.1` или `/var/run/postgresql` |
| `DB name` / `db_name` | Имя базы PowerDNS, до 256 символов. При пустом поле SINVER использует `powerdns` | `powerdns` |
| `PostgreSQL user` / `psql_user` | Пользователь PostgreSQL, до 256 символов. Нужны чтение `domains` и `records`, добавление и удаление строк `records`, а также доступ к последовательности ID записей. Полный пример прав приведён в [Быстром старте](01_Quick_Start_RU.MD) | `sinver_writer` |
| `PostgreSQL password` / `psql_password` | Пароль этого пользователя, до 256 символов. При создании пустое поле означает пустой пароль подключения | Пароль отдельной учётной записи |
| `Description` | Произвольный комментарий; разрешены несколько строк. Ограничение длины в текущей схеме не установлено | `Публичная зона приложения` |

Используйте целые десятичные числа секунд для `REFRESH`, `RETRY`, `EXPIRE` и `MINIMUM`. SINVER передаёт эти строки в SOA без преобразования и не проверяет их числовой формат; корректность и диапазон `SERIAL` также не проверяются. `MINIMUM` **не задаёт TTL записей A и AAAA**: при публикации SINVER использует TTL `3600` секунд.

Для `MNAME` и `RNAME` рекомендуется полное имя с завершающей точкой, как в таблице: экспорт BIND вставляет значения без изменения, и точка предотвращает добавление имени зоны второй раз. `RNAME` не является обычным почтовым адресом: `hostmaster@example.net` вводить нельзя. Если локальная часть почтового адреса содержит точку, её экранируют обратной косой чертой, например `dns\.admin.example.net.` для `dns.admin@example.net`.

Параметры подключения нужны только для PowerDNS. Для экспорта BIND их заполнять не требуется. Сам адрес PostgreSQL и его пользователь обязательны для **Push**; пароль может отсутствовать, если правила PostgreSQL допускают такое подключение.

Отдельного поля порта PostgreSQL нет. SINVER не передаёт параметр `port` драйверу: обычно используется `5432`, либо значение по умолчанию из окружения libpq. Запись вида `127.0.0.1:5433` в поле адреса не является настройкой порта. Настройка SSL PostgreSQL также не представлена отдельными полями SINVER.

> **Пароль хранится в SQLite без шифрования и попадает в её резервные копии.** Доступ к БД и каталогу копий предоставляйте только администратору и системной учётной записи SINVER. Назначение этих путей описано в главе [Конфигурация](02_Configuration_RU.MD).

## 9.3. Карточка и изменение зоны

1. Откройте зону по ссылке в таблице и нажмите **Edit**.
2. Измените необходимые поля и нажмите **Save**.
3. Для подготовки публикации нажмите **Go to DNS tab**. Зона будет выбрана в форме DNS.

Поле `psql_password` при открытии карточки всегда пустое; сохранённый пароль браузеру не передаётся. **Пустое поле при сохранении оставляет прежний пароль.** Чтобы заменить пароль, введите новый. Очистить уже сохранённый пароль штатной формой нельзя.

Изменение имени зоны меняет имена, которые SINVER сформирует для связанных серверов и поддоменов. Оно не переименовывает зону в PowerDNS и не удаляет записи под прежним именем. До публикации проверьте, что нужная зона существует в PowerDNS и заполнены её параметры подключения.

### Пример: добавить зону для первого сервера

1. В PowerDNS создайте `example.net` с SOA и NS по инструкции [Быстрого старта](01_Quick_Start_RU.MD).
2. В **Add zone** заполните поля значениями из таблицы. `2610071200` — условный SERIAL примера; используйте фактический SERIAL существующей SOA.
3. Для PostgreSQL укажите адрес, пользователя `sinver_writer`, БД `powerdns` и пароль, настроенные при установке.
4. Создайте сервер `web01` и выберите `example.net` в его поле **Primary zone**. Его полное имя будет `web01.example.net`.
5. Добавьте серверу IPv4 `192.0.2.10` с флагом **Primary**. При публикации SINVER сформирует `web01.example.net A 192.0.2.10`.

Для дополнительного имени `api.example.net` создайте поддомен `api` в зоне `example.net` и свяжите его с нужными IP; порядок действий описан в главе [Subdomains](06_Subdomains_RU.MD).

## 9.4. Удаление зоны

Кнопка **Delete zone** в карточке запрашивает подтверждение браузера.

- Если хотя бы один сервер использует зону как **Primary zone**, SQLite запрещает удаление. Сначала измените основную зону этих серверов или снимите её выбор.
- Если связанных серверов нет, удаление зоны также удаляет её поддомены и связи этих поддоменов с IP. Сами серверы, IP, роли и хостинги сохраняются.
- Зона и её записи в PowerDNS или BIND не удаляются: их жизненный цикл администратор обслуживает отдельно.

Перед удалением убедитесь, что данные поддоменов больше не нужны. Известные недостатки обработки ошибок и проверки полей перечислены в главе [Текущие проблемы](11_Current_Issues_RU.MD).
