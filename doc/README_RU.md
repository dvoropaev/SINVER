# SINVER: руководство администратора

SINVER — система инвентаризации серверов, хранения сведений о распределённой инфраструктуре и синхронизации этих сведений с DNS. Она помогает ответить на вопросы: какие серверы используются, у кого они размещены, какие IP-адреса им принадлежат и какие доменные имена на них указывают.

В веб-интерфейсе администратор ведёт серверы, IPv4/IPv6-адреса, поддомены, роли, хостинги и DNS-зоны. Данные инвентаризации хранятся в локальной SQLite-базе. По команде администратора SINVER обновляет записи в PostgreSQL, которую использует PowerDNS Authoritative Server, либо выгружает файл зоны для BIND9.

Руководство рассчитано на будущих пользователей SINVER, системных администраторов, разработчиков, инженеров, архитекторов программного обеспечения и начинающих ИТ-специалистов. Знакомство с SINVER не требуется. Для установки нужны базовые навыки работы с терминалом Linux и права `sudo`.

## Статус и условия использования

> **Это MVP, версия приложения и схемы БД — `0.0.0`.** Реализованы основные сценарии, но остаются ошибки и ограничения. Документация сверена с веткой `doc` на коммите `cedb107`; в ней также возможны неточности. Перед использованием проверьте описанные действия на отдельном стенде.

Перед размещением в производственной среде:

- ограничьте доступ: встроенных учётных записей и разграничения прав нет; для удалённого доступа используйте HTTPS и авторизацию на NGINX;
- подготовьте независимые резервные копии SQLite и PostgreSQL и проверьте восстановление;
- выделите тестовую DNS-зону: синхронизация заменяет управляемый набор **A, AAAA и SOA всей выбранной зоны**; отсутствующие в SINVER адресные записи могут быть удалены;
- проверьте SERIAL, DNS-кеши и ограничения прямой записи в PostgreSQL; DNSSEC и вторичные DNS-серверы требуют отдельной проверки;
- изучите [текущие проблемы](11_Current_Issues_RU.md) и оцените, допустимы ли они для вашей инфраструктуры.

SINVER не опрашивает серверы и не обнаруживает инфраструктуру автоматически: сведения вводит администратор. Сохранение карточки меняет инвентаризацию; публикация в DNS выполняется отдельно.

## Обозначения в примерах

| Обозначение | Значение |
| --- | --- |
| `infra.example.net` | Учебная DNS-зона; замените своей зоной при реальном развёртывании |
| `app-01` | Имя первого сервера в инвентаризации |
| `192.0.2.10`, `192.0.2.53`, `2001:db8::10` | Адреса для документации; они не обозначают доступные серверы |
| `sinver.example.org` | Пример внешнего имени веб-интерфейса; для сертификата нужно ваше настоящее доменное имя |
| `Create`, `Edit`, `Save`, `Push` | Точные подписи кнопок в интерфейсе |
| `sudo` | Выполнение команды с административными правами |
