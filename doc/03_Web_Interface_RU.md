# 3. WEB-интерфейс

[← Назад](02_Configuration_RU.md) · [Содержание](README_RU.md#содержание) · [Вперёд →](04_Servers_RU.md)

## Вкладки и назначение

Откройте адрес SINVER в браузере. При стандартном локальном запуске это `http://127.0.0.1:8080`; при доступе через NGINX — настроенный HTTPS-адрес. Главная страница перенаправляет на **Servers**.

Названия элементов интерфейса преимущественно английские. В руководстве используется исходная подпись с русским объяснением.

| Вкладка | Перевод | Для чего используется |
|---|---|---|
| [Servers](04_Servers_RU.md) | Серверы | Инвентаризация серверов, их размещения, ролей и адресов |
| [IP addresses](05_IP_Addresses_RU.md) | IP-адреса | Адреса IPv4/IPv6, их принадлежность серверам и выбор основного адреса |
| [Subdomains](06_Subdomains_RU.md) | Поддомены | Дополнительные DNS-имена типов `A` и `AAAA`, связанные с IP-адресами |
| [Roles](07_Roles_RU.md) | Роли | Справочник назначения объектов и цветов для визуального различения |
| [Hostings](08_Hostings_RU.md) | Хостинги | Справочник мест размещения серверов, ссылки и даты оплаты |
| [Zones](09_Zones_RU.md) | Зоны | DNS-зоны, параметры `SOA` и подключение к PostgreSQL PowerDNS |
| [DNS](10_DNS_RU.md) | DNS | Предварительный просмотр и отправка данных в PowerDNS, выгрузка файла зоны для BIND9 |

Первые шесть вкладок работают с инвентарной базой SQLite. Изменение карточки **не отправляет данные в PowerDNS автоматически**. Отправка выполняется отдельно во вкладке **DNS** после предварительного просмотра и подтверждения.

## Как связаны объекты

| Объект | Связи |
|---|---|
| Сервер | Может иметь одну основную зону, одну роль и один хостинг; содержит любое количество IP-адресов |
| IP-адрес | Принадлежит ровно одному серверу; может иметь собственную роль. У сервера может быть только один основной IP-адрес среди IPv4 и IPv6 |
| Поддомен | Принадлежит одной зоне, может иметь свою роль и связываться с несколькими IP-адресами |
| Роль | Может назначаться нескольким серверам, IP-адресам и поддоменам независимо |
| Хостинг | Может содержать несколько серверов |
| Зона | Может быть основной для нескольких серверов и содержать несколько поддоменов |

Например, сервер `app-01` имеет основную зону `infra.example.net` и основной IPv4-адрес `192.0.2.10`. SINVER формирует из этой связи запись `app-01.infra.example.net A 192.0.2.10`. Дополнительный поддомен `api` той же зоны можно связать с этим IP, чтобы сформировать `api.infra.example.net A 192.0.2.10`.

Роль и хостинг помогают организовать инвентаризацию; сами по себе они не создают DNS-записи. Подробные правила формирования записей приведены в главе [DNS](10_DNS_RU.md).

Удобный порядок заполнения: **зоны и необходимые справочники → серверы → IP-адреса → дополнительные поддомены → DNS**. Роли и хостинги необязательны. Для дополнительных поддоменов зону и IP-адреса создайте заранее.

## Общие операции

### Список, фильтры и сортировка

На вкладках инвентаризации верхний блок содержит фильтры и параметр **Sort by** — «Сортировать по». Ниже показаны таблица объектов и форма добавления.

| Элемент | Действие |
|---|---|
| `Any` | Не ограничивать результаты этим фильтром |
| `Apply` | Применить выбранные фильтры и сортировку к списку |
| `Reset` | Снять фильтры и вернуть список к исходным параметрам |
| Ссылка на имя объекта или IP | Открыть карточку объекта |
| `—` | Значение отсутствует |

`Apply` в блоке фильтров изменяет только отображение списка. Если выбрано несколько фильтров, должны выполняться все их условия. Набор фильтров отличается между вкладками и описан в соответствующих главах.

Цветные точки помогают различать роли объектов. Их источник и правила выбора цвета приведены в главе [Roles](07_Roles_RU.md).

### Добавление

1. Заполните форму **Add …** — «Добавить …» внизу нужной вкладки.
2. Выберите связанные объекты из списков. Значение **None** — «Нет» — означает, что необязательная связь не назначена.
3. Нажмите **Create** — «Создать».
4. Проверьте сообщение об успешном создании и появление объекта в списке. При ошибке прочитайте сообщение и исправьте ввод.

Доступные значения списков берутся из уже созданных объектов. Если нужной роли, зоны или хостинга нет, сначала добавьте её в соответствующий справочник.

### Просмотр и изменение

1. Откройте карточку по ссылке в таблице.
2. Нажмите **Edit** — «Редактировать»: поля станут доступны для изменения.
3. Внесите изменения и нажмите **Save** — «Сохранить».

До нажатия `Save` изменения существуют только в открытой форме. Отдельной кнопки отмены нет: чтобы отказаться от несохранённых изменений, заново откройте карточку или перейдите на другую страницу. Карточки также показывают связанные объекты; доступные ссылки позволяют переходить между ними.

### Удаление

Кнопка **Delete …** — «Удалить …» находится в карточке. Браузер запрашивает подтверждение. **Удаление может затронуть связанные данные**, поэтому перед подтверждением ознакомьтесь с последствиями в главе нужной вкладки.

Встроенной команды отмены удаления нет. Восстановление инвентаризации из резервной копии описано в [конфигурации](02_Configuration_RU.md#ручное-восстановление-sqlite).

## Сообщения и ошибки

После операции интерфейс показывает сообщение: зелёное сообщает об успехе, красное — об ошибке. Например, **Server created.** означает «Сервер создан», а **Invalid IP format.** — «Неверный формат IP-адреса».

В случае **Internal error** — «Внутренняя ошибка» — операция не завершилась штатно. Проверьте текущее состояние объекта перед повторной отправкой: составная операция может успеть выполнить часть изменений. Известные ограничения и способы их обхода собраны в главе [Текущие проблемы](11_Current_Issues_RU.md).

Формы защищены от подделки межсайтовых запросов — CSRF. Браузер автоматически передаёт токен вместе с формой. Если появился ответ:

```text
CSRF validation failed. Reload the page and submit the form again.
```

обновите страницу, повторно заполните форму и отправьте её. Это необходимо, в частности, после перезапуска SINVER. Для работы форм браузер должен принимать cookie сайта.

**Maintenance mode** — «Режим обслуживания» — заменяет все вкладки при необходимости обновления или при ошибке проверки базы. Действия администратора описаны в [разделе о запуске и обслуживании](02_Configuration_RU.md#проверка-базы-при-запуске-и-режим-обслуживания).

Встроенных учётных записей, разграничения прав и режима только чтения в интерфейсе нет. Все посетители, получившие доступ к SINVER, могут изменять данные и выполнять операции DNS. Для внешнего доступа настройте ограничения в NGINX по [быстрому старту](01_Quick_Start_RU.md).
