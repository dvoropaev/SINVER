# Запуск
Запуск предполагается командой:
./sinver.py ./db.sqlite

Если файла ./db.sqlite нет, sinver сообщает об этом и предлагает его создать
Если файл есть, но он пустой - sinver говорит что базы данных нет, и предлагает создать
Если база данных есть, но с ней что-то не так - sinver пишет подробности проблемы и завершается с ошибкой
Если все прошло успешно - sinver сообщает об успешном запуске и выводит URL с номером порта.
# Описание интерфейса

Дизайн современный, мягкий, округлый
светлые кремовые цвета

В шапке расположено меню с вкладками

Основной интерфейс web-приложение состоит из нескольких вкладок:

## Основные вкладки
Каждая вкладка представляет из себя список элементов определенной таблицы

над списком для каждого отображаемого параметра можно сделать сортировку и фильтрацию.
должна быть кнопка "применить" (чтобы применить фильтры) и "сбросить" (чтобы сбросить фильтры)

если для элементов таблицы предполагается цвет (роли, сервера, поддомены, ip-адреса), то создается колонка (самая первая), в которой отображаются цвета элементов в виде кружочков:
кружочек имеет черную окантовку, закрашен цветом элемента.
Если цвет у элемента отсутствует - то кружочка нет

При наведении курсора на строку, вся строка немного подсвечивается

Если у элемента есть description, то при наведении на него отображается подсказка (не более 50 первых символов)

Каждый элемент кликабельный, при нажатии на элемент открывается страница с подробной информацией об этом объекте.
При этом, поля для редактирования по умолчанию не доступны. Чтобы они стали доступными - необходимо нажать кнопку редактировать. Для сохранения результатов необходимо нажать кнопку "сохранить".

поле для редактирования description должно быть многострочным и не маленьким. При необходимости у него должна быть функция скроллинга

Также на вкладке должно быть предусмотрено добавление и удаление элементов

В карточках различных элементов есть дополнительные блоки, которые размещены в самом низу

### Servers - список серверов
отображаются следующие поля:
цвет
hostname (если есть primary zone, то выводится hostname + "." + zone)
primary ip (если есть)
ip адреса (если ip адресов несколько, то они отображаются в нескольких строках)
роль
хостинг
оплачен до

Поведение:
- сервер кликабелен и открывает карточку сервера;
- в карточке сервера можно редактировать hostname, primary zone, роль, хостинг и полное описание;
- в карточке сервера есть отдельный блок со списком IP и поддоменов, которые ведут на этот сервер;
- если у сервера указана primary zone, в списке и в заголовке карточки отображается FQDN в формате `hostname.zone`, иначе только `hostname`;
- поле `primary ip` в списке вычисляется автоматически по IP с `is_primary = true` и не редактируется напрямую из карточки сервера;
- при смене primary IP в карточке IP-адреса значение в колонке `primary ip` для сервера обновляется сразу;
- если у сервера нет IP-адресов, в колонках `primary ip` и `ip адреса` отображается пустое значение (или `—`);
- при удалении сервера требуется подтверждение, после удаления удаляются связанные IP-адреса и связи `Поддомен → IP` для этих IP.

### IP-адреса - список адресов (IPv4 и IPv6)
Отображаются следующие поля:
цвет
тип адреса (IPv4/IPv6)
IP-адрес
сервер (hostname (если есть primary zone, то выводится hostname + "." + zone))
роль
primary

Поведение:
- если `is_primary = true`, в колонке `primary` отображается отметка (например, `Yes`/`Primary`);
- если `is_primary = false`, поле пустое;
- IP-адрес кликабелен и открывает карточку IP-адреса;
- в карточке IP-адреса можно менять сервер, роль и флаг `is_primary`;
- в карточке IP-адреса есть отдельный блок со списком доменов, указываюзих на этот IP;
- при установке `is_primary = true` для одного IP у сервера, у остальных IP этого сервера `is_primary` автоматически сбрасывается в `false`.

### Subdomains - список поддоменов
Отображаются следующие поля:
цвет
тип записи (A/AAAA/CNAME/TXT и т.д.)
имя поддомена
зона
ip адреса (если ip адресов несколько, то они отображаются в нескольких строках)
роль


Поведение:
- поддомен кликабелен и открывает карточку поддомена;
- в карточке можно редактировать тип записи, имя поддомена, зону и список привязанных IP;
- в карточке поддомена есть отдельный блок со списком серверов, на которые ведет этот поддомен;
- список IP хранится через связь `Поддомен → IP`, изменения выполняются через добавление/удаление связей;
- если у поддомена нет собственной роли, цвет определяется по приоритету ролей из README.

### Roles - список ролей
Отображаются следующие поля:
цвет
имя роли
описание  (не более 50 первых символов)

Поведение:
- роль кликабельна и открывает карточку роли;
- в карточке можно изменить имя, полное описание и цвет;
- в карточке роли есть отдельные блои для серверов, поддоменов и IP, которые имеют эту роль;
- цвет выбирается через color-picker или ввод HEX-кода;
- удаление роли должно требовать подтверждение;
- при удалении роли связанные объекты (сервера/IP/поддомены) продолжают существовать, а их поле роли становится `null`.

### Hostings - список хостингов
Отображаются следующие поля:
имя
ссылка
оплачен до
описание (не более 50 первых символов)


Поведение:
- хостинг кликабелен и открывает карточку хостинга;
- в карточке можно редактировать имя, ссылку, дату оплаты и полное описание;
- в карточке хостинга есть отдельный блок со списком серверов, которые относятся к этому хостингу;
- ссылка отображается как текст и, при наличии, может открываться в новой вкладке;
- для даты `оплачен до` используется удобный date-picker.

### Zones - список зон
Отображаются следующие поля:
зона
MNAME
RNAME
SERIAL
REFRESH
RETRY
EXPIRE
MINIMUM
psql адрес
psql пользователь
описание  (не более 50 первых символов)

Поведение:
- зона кликабельна и открывает карточку зоны;
- в карточке можно редактировать все поля зоны, включая параметры подключения к PostgreSQL;
- пароль `psql` отображается маской и сохраняется только при явном изменении;
- для зоны должна быть доступна быстрая навигация к вкладке DNS для запуска `Push`/`generate config`.

## Вкладка DNS
Это отдельная вкладка, предназначенная для обновления зон на DNS серверах.
Способ обновления зон описан в README.md (пункт "Обновление зон на DNS-серверах")
состоит из двух панелей:
### PowerDNS + PostgreSQL
Пользователь выбирает зону, которую хочет обновить и нажимает "Push". Далее все согласно README.md.
### Bind9
Пользователь выбирает зону, а затем нажимает "generate config". Генерируется .db файл с зоной и выдается пользователю.
